# 多模态大模型演进史（2015-2026）

> 从 CNN+RNN 到 CLIP 双塔，从连接器式 VLM 到原生多模态，视觉-语言融合的十年进化之路

---

## 写在前面

这份演进史追踪的是**多模态大模型（Multimodal Large Language Model, MLLM）**的发展脉络。和 LLM / ASR / SD 演进史的写法一致——分阶段、每个模型交代"前置条件"和"核心改进"。

多模态技术经历了**六个范式跃迁**，每次跃迁都在解决上一轮留下的麻烦，同时引入新的问题：

```
2015-18 ── CNN+RNN 浅层融合 ─── "迈出图文理解第一步"
2019-20 ── 跨模态 Transformer ── "BERT 式预训练进入视觉"
2021-22 ── 对比学习双塔 ─────── "CLIP 建立共享语义空间"
2023-24 ── 连接器式 VLM ─────── "Frozen LLM + Frozen ViT"
2024    ── 原生多模态 ────────── "端到端训练，动态分辨率"
2025-26 ── 统一理解+生成+Agent ─ "全能模型时代"
```

---

## 第一阶段：浅层融合时代（2015-2018）——"能不能让 AI 看图说话"

### 前置条件

在多模态技术起步之前，计算机视觉和自然语言处理是两个完全独立的领域：
- **CV** 做分类/检测/分割，输出是类别标签或 bounding box
- **NLP** 做翻译/分类/生成，输入输出都是文本

没有人思考"怎么让 AI 同时理解图像和文字"。

### 2014-2015 — Show and Tell / Show, Attend and Tell · 论文开源

**"Show and Tell: A Neural Image Caption Generator"（Vinyals et al., 2015）**
**"Show, Attend and Tell: Neural Image Caption Generation with Visual Attention"（Xu et al., 2015）**

| 维度 | 说明 |
|------|------|
| 架构 | Show and Tell: **CNN（VGG/Inception）+ LSTM**（编码器-解码器）|
| 核心贡献 | **Image Captioning 的开山之作**——第一次用 CNN 提取图像特征 + RNN 生成描述文字。Show, Attend and Tell 引入注意力机制：解码每一步时，模型"关注"图像的不同区域 |
| 局限 | 只能做图像描述，不能做 VQA 或对话。CNN+RNN 的融合很浅——图像特征只在 LSTM 初始状态注入一次 |

### 2015-2017 — VQA（Visual Question Answering）· 论文开源

| 维度 | 说明 |
|------|------|
| 核心贡献 | **定义了多模态推理任务**——给定图像 + 问题（"图中几个人？"），模型输出答案。VQA v1.0 数据集（2015）成了多模态领域的事实标准 benchmark |
| 局限 | 当时的模型基本是"图像特征 + 文本特征 → 拼接 → MLP → 答案"，融合非常浅层 |

### 2017 — Bottom-Up Top-Down Attention · 论文开源

**"Bottom-Up and Top-Down Attention for Image Captioning and Visual Question Answering"（Anderson et al., CVPR 2018）**

| 维度 | 说明 |
|------|------|
| 核心改进 | **用 Faster R-CNN 的目标检测区域替代 CNN 网格特征**——模型不再看固定的网格，而是看"有意义的物体区域"（猫、人、车）。Top-Down Attention 让语言解码器动态决定关注哪些检测区域 |
| 影响 | 这个"检测特征 + 注意力"范式统治了 2017-2020 年的多模态领域 |

### 阶段总结

```
第一阶段的贡献:
  - 证明了"CNN 看 + RNN 说"这个路线可行
  - VQA 和 Captioning 定义了多模态的核心任务
  - Bottom-Up Attention + Detection Features 成为接下来几年的标准范式

核心局限:
  1. 依赖目标检测（Faster R-CNN）—— 慢且贵，无法迁移
  2. 融合浅层 —— 图像特征只在输入层注入，没有深层交互
  3. 没有预训练 —— 每个任务从头训，没有通用的多模态预训练配方
  4. 数据集小 —— COCO Captions（~120K）是最好的了
```

## 第二阶段：跨模态 Transformer 预训练（2019-2020）——"BERT 的成功启发视觉"

### 前置条件

BERT（2018）在 NLP 上的成功——Masked Language Model + Next Sentence Prediction 预训练、下游微调——带来了一个自然的想法：能不能把 BERT 的预训练范式应用到多模态上？核心思路是用"图文对"数据做 Masked Language Modeling + Image-Text Matching。

另一条线：2017 年 Transformer 提出后，Vision Transformer（ViT）还没出现（2021），但 Transformer 的 Encoder-only 架构已经被 NLP 验证。

### 2019 — ViLBERT / LXMERT / VisualBERT · 论文开源

| 模型 | 机构 | 时间 | 架构 | 核心改进 |
|------|------|------|------|---------|
| **ViLBERT** | JHU / Microsoft | 2019.04 | 双流 Transformer（图像流 + 文本流 + Co-Attention）| 两个独立的 Transformer 处理图像和文本，通过 Co-Attention 层交互。预训练任务：MLM + ITM + Masked ROI |
| **LXMERT** | UNC Chapel Hill | 2019.08 | 双流 Transformer（图像流 + 文本流 + Cross-Attention）| 三个预训练任务：MLM + ITM + VQA。在 VQA、GQA、NLVR2 等 benchmark 上达到当时 SOTA |
| **VisualBERT** | Harvard | 2019.08 | 单流 Transformer | 将图像检测区域特征作为额外 token 拼入 BERT，用 MLM + ITM 做预训练 |

| 维度 | 说明 |
|------|------|
| 统一特征 | 这些模型都使用 **Faster R-CNN 检测区域特征**（36-100 个区域/图），作为图像侧输入 |
| 预训练数据 | **Conceptual Captions（3M 图文对）** or COCO（120K）——规模很小 |
| 核心贡献 | **证明了"BERT 式预训练 + 下游微调"在多模态上也能工作**。LXMERT 在 VQA 上达到当时最高分 |
| 局限 | 依赖目标检测器（Faster R-CNN）→ 推理慢、无法迁移到非检测任务；预训练数据规模远小于 NLP |

### 2020 — UNITER · 论文开源

**"UNITER: UNiversal Image-TExt Representation Learning"（Chen et al., 2020）**

| 维度 | 说明 |
|------|------|
| 架构 | 单流 Transformer（图像区域 token + 文本 token -> 统一序列）|
| 核心改进 | **四个预训练任务**：MLM + ITM + MRM（Masked Region Modeling）+ WRA（Word-Region Alignment）。在 6 个下游任务上同时达到 SOTA |
| 参数量 | Base 110M / Large ~300M |
| 局限 | 仍然依赖区域检测特征；预训练需要等长的图文对，视频/音频等其他模态无法处理 |

### 阶段总结

```
第二阶段的贡献:
  - 跨模态 Transformer + 预训练范式 = 多模态模型的"BERT 时刻"
  - 证明了 MLM + ITM 在图文领域同样有效

核心局限:
  1. 依赖 Faster R-CNN 的区域特征 —— 推理速度慢、训练成本高、无法迁移
  2. 预训练数据量太小（3M-10M 级别）—— 限制了模型能力
  3. 每个模型只能在"图像+文本"上工作，无法扩展到其他模态
  4. 模型参数量小（100M-300M），Scale Law 还没有被验证
```

## 第三阶段：对比学习双塔时代（2021-2022）——"CLIP 引爆了视觉-语言理解"

### 前置条件

2020 年前后，NLP 领域的 GPT-3（175B）和 Vision 领域的 ViT（Vision Transformer）各自有了突破：
- **ViT（2020.10）** 证明了 Transformer 可以直接在图像 patch 上工作，不需要 R-CNN 检测器
- **对比学习**在 CV 领域（SimCLR、MoCo）被验证有效
- **大规模数据**的爬取和清洗有了更好的基础设施

多模态领域需要一个**不需要检测器、不需要微调、在 4 亿图文对上预训练**的通用视觉编码器。

### 2021.01 — CLIP（OpenAI）· 论文开源

**"Learning Transferable Visual Models From Natural Language Supervision"（Radford et al., ICML 2021）**

| 维度 | 说明 |
|------|------|
| 架构 | **双塔结构**：Image Encoder（ViT/ResNet）+ Text Encoder（Transformer），对比学习 |
| 训练数据 | **400M 图文对**（WebImageText）——从互联网爬取的 noisy 数据 |
| 训练方式 | **对比损失（InfoNCE）**：batch 内 N 个图文对，拉近匹配对（N 个正样本），推远 N²-N 个不匹配对 |
| 核心改进 | **Zero-shot 图像分类**——在 ImageNet 上达到 76.2% 准确率，**无需任何 ImageNet 训练数据**，全靠图文对比学习。匹配了一个监督 ResNet-50 |
| 参数量 | ViT-L/14 ~430M（视觉编码器）+ ~340M（文本编码器）|
| 影响 | **~50,000+ 引用**。CLIP 成为多模态领域事实标准的视觉编码器——后续几乎所有 VLM（LLaVA、BLIP-2、Qwen-VL、InternVL）都使用 CLIP 风格的 ViT 作为视觉编码器 |

```
CLIP 训练:
  图像 ──→ Image Encoder ──→ 图像嵌入 I
  文本 ──→ Text Encoder  ──→ 文本嵌入 T

  损失: L = -log(exp(I·T_pos/τ) / Σ exp(I·T_i/τ))
        ↑
  正样本对（匹配的图文）的 cosine similarity → 1
  负样本对（不匹配的图文）的 cosine similarity → 0

关键洞察:
  - 不需要昂贵的标注数据——用互联网上的图文对即可
  - 不需要目标检测器——ViT 直接在图像上提取 patch-level 特征
  - 零样本迁移——训练时看不到任何分类标签，但推理时可以直接做分类
```

### 2021.05 — ALIGN（Google）· 论文

**"Scaling Up Visual and Vision-Language Representation Learning With Noisy Text Supervision"（Jia et al., 2021）**

| 维度 | 说明 |
|------|------|
| 架构 | 双塔结构（类似 CLIP）|
| 训练数据 | **1.8B 图文对**——比 CLIP 的 400M 大 4.5×，但数据更嘈杂 |
| 核心发现 | **证明了"数据量可以弥补数据质量"**——即使是很 noisy 的图文对，scale 到 1B+ 也能训出好的视觉表示 |
| 影响 | 和 CLIP 一起验证了"对比学习 + 大规模图文对"的有效性 |

### 2022.04 — Flamingo（DeepMind）· 论文

**"Flamingo: a Visual Language Model for Few-Shot Learning"（Alayrac et al., NeurIPS 2022）**

| 维度 | 说明 |
|------|------|
| 参数量 | **80B**——当时最大的视觉-语言模型 |
| 架构 | **冻结的 CLIP ViT（视觉编码器）+ 冻结的 Chinchilla（LLM）+ GATED XATTN-DENSE 层** |
| 核心改进 | **(1) 冻结两个骨干模型，用 GATED Cross-Attention 桥接**——不需要重新训练视觉或语言模型；(2) **支持交错图文序列**（图-文-图-文交替输入）；(3) **Few-shot 能力**——只需要几个图文示例就能适应新任务 |
| 影响 | **"GPT-3 时刻 for multimodal"**——证明了"在冻结的 LLM 上通过交叉注意力桥接视觉信息"这条路线可行，是 BLIP-2 和后续连接器式 VLM 的直接先驱 |

```
Flamingo 的 GATED XATTN-DENSE:
  
  Frozen LLM Decoder Layer:
    x → Self-Attn → GATED Cross-Attn → FFN → x'
                      ↑        ↑
                  Q=文本    K,V=视觉特征（来自 ViT）
                  
  Gating mechanism:
    GATED Cross-Attn = tanh(α) · Cross-Attn(Q, K, V)
                         ↑
    α 是可学习的标量，初始化为 0
    训练开始时：tanh(0)=0 → Cross-Attn 输出为 0 → 不干扰 Frozen LLM
    训练中：α 渐大 → 视觉信息逐步注入 ← 和 ControlNet 的 Zero Convolution 异曲同工！
```

### 2022.01 — BLIP（Salesforce）· 论文开源

**"BLIP: Bootstrapping Language-Image Pre-training for Unified Vision-Language Understanding and Generation"（Li et al., ICML 2022）**

| 维度 | 说明 |
|------|------|
| 架构 | **MED（Multimodal Mixture of Encoder-Decoder）**——一个模型同时支持理解（Encoder）+ 生成（Decoder）|
| 核心改进 | **(1) CapFilt（Captioning + Filtering）**——用模型生成图像描述，再用模型过滤低质量的；(2) **统一的预训练架构**——理解任务用 Encoder 模式，生成任务用 Decoder 模式 |
| 参数量 | Base 223M / Large 400M |
| 影响 | CapFilt 成为后续多模态数据增强的标准方法 |

### 2022.06 — BLIP-2（Salesforce）· 论文开源

**"BLIP-2: Bootstrapping Language-Image Pre-training with Frozen Image Encoders and Large Language Models"（Li et al., ICML 2023）**

| 维度 | 说明 |
|------|------|
| 架构 | **Frozen ViT + Q-Former + Frozen LLM** |
| 核心改进 | **(1) Q-Former（Querying Transformer）**——轻量级 Transformer，通过可学习的 query tokens 从冻结的 ViT 中"查询"相关信息；(2) **两阶段训练**——第一阶段从冻结 ViT 提取视觉特征，第二阶段从冻结 LLM 学习文本生成 |
| 参数量 | 总 7B-13B（Q-Former 仅 ~188M，其余都冻结）|
| 影响 | **Q-Former 成为连接器式 VLM 的重要范式**——直到 LLaVA 的 MLP Projector 出现之前，Q-Former 是最主流的视觉-语言桥接方案 |

```
Q-Former 工作原理:
  
  可学习的 query tokens (32 个) ← 随机初始化
            │
            ▼
  ┌─────────────────┐
  │  Q-Former       │
  │  Cross-Attn:    │
  │  Q = query      │ ← 这 32 个 query 问问题
  │  K,V = ViT 输出  │ ← Frozen ViT 回答
  └────────┬────────┘
           │
           ▼
  32 个"压缩后"的视觉特征
  注入 Frozen LLM

优势: 32 个 query 可以"重点关注"图像中与文本相关的区域
        → 比全序列 ViT token 更高效、比单 CLS token 保留更多信息
局限: 32 个 query 依然是"信息瓶颈"
        → 需要更细粒度理解时（OCR、对象关系），query 数量不够
```

### 2022.12 — PaLM-E（Google）· 论文

| 维度 | 说明 |
|------|------|
| 参数量 | **562B**（PaLM + ViT + 传感器特征）|
| 架构 | PaLM（540B）+ ViT + 机器人传感器编码器 |
| 核心贡献 | **Embodied（具身）多模态模型**——不只看图，还看机器人传感器数据。让 LLM 直接控制机器人，输入图像+指令→输出动作序列 |
| 意义 | 开辟了"多模态 + 具身智能"的方向 |

### 阶段总结

```
第三阶段的贡献:
  - CLIP 提供了大规模、免检测器、零样本的通用视觉编码器
  - Flamingo / BLIP-2 验证了"Frozen ViT + Frozen LLM"的模块化路线
  - 从 4 亿对（CLIP）到 18 亿对（ALIGN）的数据规模验证了 Scaling

核心局限:
  1. 双塔对比学习（CLIP）是粗粒度的——整图↔整句对齐，缺乏细粒度（物体位置、OCR）
  2. Q-Former 的 query 数量限制了信息量
  3. 视觉和语言模型都是"冻结的"——无法端到端优化，连接器成为瓶颈
  4. 不支持多图输入或高分辨率输入
```

## 第四阶段：连接器式 VLM 大爆发（2023-2024 初）——"LLaVA 引爆开源，GPT-4V 定义商业"🔑 最关键的变革期

### 前置条件

2022-2023 年是 LLM 的大爆发期——ChatGPT / GPT-4 / LLaMA / Vicuna……语言模型能力达到了前所未有的高度。与此同时，CLIP 在多模态社区已经验证了其有效性。

"能不能把最强的 LLM 和最强的视觉编码器连起来"——这个想法在 2023 年得到了终极验证。

### 2023.04 — LLaVA（UW-Madison / Microsoft）· ✅ 开源

**"Visual Instruction Tuning"（Liu et al., NeurIPS 2023）**

| 维度 | 说明 |
|------|------|
| 架构 | **CLIP ViT-L/14 + MLP Projector + Vicuna/LLaMA（7B/13B）** |
| 训练 | **两阶段训练**：(1) 特征对齐——558K 图文对，训 MLP Projector；(2) 视觉指令微调——150K GPT-4 生成的指令数据 |
| 核心改进 | **(1) 极简单的架构——没有 Q-Former，没有 Cross-Attention**，只有一个 MLP 将 ViT 的输出映射到 LLM 的 embedding 空间；(2) **视觉指令微调**——用 GPT-4 生成"图像+指令"对，教会模型对话式回答视觉问题 |
| 参数量 | 7B / 13B |
| 训练成本 | **极低**——8 张 A100 训一天 |
| 影响 | **开源 VLM 的标杆**。LLaVA 证明了"简单的 MLP Projector + 指令微调"也能达到接近 GPT-4V 的视觉理解能力。LLaVA-1.5（2024.01）改用 MLP（而非单层 Linear），加入学术 VQA 数据，达到了最强开源 VLM 水平 |

```
LLaVA 架构（极简）:

  图像 ──→ CLIP ViT ──→ 576 token（224² 图像）
                              │
                         MLP Projector（2层）
                              │
                              ▼
  576 token → LLM（Vicuna/LLaMA）
                              │
  文本 prompt → LLM ←─────────┘
                              │
                    输出文本响应

训练（两阶段）:
  Stage 1: 冻结 ViT + 冻结 LLM，只训 MLP（558K 图文对，学习对齐）
  Stage 2: 冻结 ViT，MLP + LLM 全参数微调（150K 指令数据）

对比 Q-Former:
  Q-Former: 32 query token → "选择性提取" → 信息瓶颈
  LLaVA: 576 token → "全送进去" → 信息更多，但计算量更大
  
  LLaVA 的假设: LLM 足够大（7B+ 参数），可以自己学会处理视觉 token
                → 不需要专门的信息提取器
```

### 2023.05 — InstructBLIP（Salesforce）· ✅ 开源

**"InstructBLIP: Towards General-purpose Vision-Language Models with Instruction Tuning"（Dai et al., 2023）**

| 维度 | 说明 |
|------|------|
| 架构 | BLIP-2 的 Q-Former + Frozen LLM + 指令微调 |
| 核心改进 | 在 BLIP-2 基础上引入**指令感知的视觉特征提取**——query 根据指令动态调整关注区域。训练时混合 26 个公开 VLM 数据集，统一为指令格式 |
| 效果 | 在 13 个 benchmark 上达到当时最佳 |

### 2023.09 — GPT-4V（OpenAI）· ❌ 闭源

**"GPT-4V: GPT-4 with Vision" —— 第一个达到商用水平的商业多模态大模型**

| 维度 | 说明 |
|------|------|
| 架构 | 未公开（推测为 LLM + 视觉适配器，类似 LLaVA 的设计但规模 ×100）|
| 核心改进 | **(1) 第一次在 GPT-4 级别模型中加入视觉理解能力**；(2) 多图输入、图像标注、OCR、图表理解等综合能力远超之前的任何模型；(3) 推理时可以通过文字+图像的方式交互 |
| 能力 | 理解复杂图表、医学影像、漫画、手写笔记等——**人类级别的视觉理解** |
| 影响 | 定义了"商业化多模态大模型应该做到什么水平"。所有后续开源 VLM（LLaVA-1.5、Qwen-VL、InternVL）都以追赶 GPT-4V 为目标 |

### 2023.09 — Qwen-VL（阿里巴巴）· ✅ 开源

| 维度 | 说明 |
|------|------|
| 架构 | ViT + Q-Former + Qwen-7B |
| 核心改进 | 原生支持**中文 + 英文**双语输入。开放中英双语的 VLM 训练配方 |
| 参数量 | 7B / 14B |
| 影响 | 国内首个高质量开源 VLM，验证了"中文多模态"路线的可行性 |

### 2023.12 — Gemini 1.0（Google DeepMind）· ❌ 闭源

| 维度 | 说明 |
|------|------|
| 架构 | **Natively Multimodal（原生多模态）**——从零开始同时在文本、图像、音频、视频上训练 |
| 核心改进 | **(1) 原生多模态——不是 LLM + 视觉适配器，而是从训练第一天就是多模态架构**；(2) Gemini Ultra 在 MMLU 上达到 90.0%——第一个超越人类专家的模型；(3) 三个规格（Ultra / Pro / Nano）覆盖云端到端侧 |
| 意义 | 宣告了"原生多模态"路线的可行性——与 GPT-4V 的 LLM-first 路线不同，Gemini 从一开始就设计为多模态架构 |

### 2023.12 — CogVLM（智谱 AI / 清华）· ✅ 开源

| 维度 | 说明 |
|------|------|
| 参数量 | **18B** |
| 架构 | ViT + LLaMA + **Visual Expert Module**（在 LLM 每层注入视觉专家模块，QKV 各一套）|
| 核心改进 | **Deep Visual-Language Fusion**——不是在输入层注入图像 token，而是在 LLM 每层的 Self-Attention 中加入额外的视觉 QKV，实现更深层的图文交互 |
| 影响 | 证明了"在 LLM 内部深层融合视觉"比"只在输入层投影"效果更好——但计算量也更大 |

### 阶段总结

```
第四阶段的贡献:
  - LLM（Vicuna/LLaMA/Qwen）成为 VLM 的"大脑"
  - LLaVA 用极简架构验证了 MLP Projector 的有效性
  - GPT-4V 定义了商业多模态的标准
  - Gemini 打开了"原生多模态"的方向

核心局限:
  1. ViT 分辨率上限（224×224/336×336）——高分辨率图像需要额外处理
  2. 单图输入为主——多图理解能力弱
  3. 连接器（MLP/Q-Former）仍是信息瓶颈
  4. 训练时视觉编码器通常是冻结的——无法端到端优化
```

## 第五阶段：原生多模态训练（2024）——"端到端训练，动态分辨率"

### 前置条件

2023 年的 VLM 遇到几个瓶颈：
- **分辨率锁死**——ViT 固定 224/336 输入，处理高清图片只能 downsample，丢失细节
- **视觉编码器冻结**——CLIP ViT 权重在 VLM 训练中不动，无法针对性优化
- **单图限制**——多图/视频输入的能力很弱

2024 年解决了这些问题的同时，GPT-4o 和 Gemini 1.5 Pro 重新定义了多模态的能力边界。

### 2024.02 — Gemini 1.5 Pro（Google DeepMind）· ❌ 闭源

| 维度 | 说明 |
|------|------|
| 核心改进 | **10M token 上下文窗口**——可以处理整部电影（视频帧+音频+字幕）作为输入 |
| 关键能力 | 多模态海洋寻针——在一段 10 小时视频中检索一个特定场景，准确率接近 100% |
| 影响 | 重新定义了"多模态模型能处理多大输入"的上限 |

### 2024.04 — InternVL 1.5（上海 AI Lab）· ✅ 开源

| 维度 | 说明 |
|------|------|
| 架构 | **大规模 ViT（InternViT-6B）+ QLLaMA（Q-Former 风格）+ InternLM2** |
| 核心改进 | **(1) 动态分辨率**——图像 > 224² 时切分成多个 patch，每个 patch 独立编码再合并；(2) **高清 OCR**——原生支持 4K 分辨率图像的文字读取 |
| 参数量 | 7B / 20B / 40B |
| 影响 | 证明了"放大视觉编码器（6B）同样带来收益"——视觉编码器不再是轻量组件 |

### 2024.05 — GPT-4o（OpenAI）· ❌ 闭源

| 维度 | 说明 |
|------|------|
| 核心改进 | **Omni-Modal：实时处理文本+图像+音频**。音频端到端处理——输入语音直接走 audio model 而非先 ASR 再 LLM。音频响应延迟降到 232ms（平均 320ms）——达到人类对话速度 |
| 能力 | MMMU 69.1%（当时最高）|
| 意义 | **"全能模型"时代开启**——一个模型同时理解文字、图像、语音、音乐，输出文本和语音 |

### 2024.07 — Qwen2-VL（阿里巴巴）· ✅ 开源

| 维度 | 说明 |
|------|------|
| 架构 | EVA-CLIP ViT + Qwen-2 LLM（7B/72B）|
| 分辨率 | **动态分辨率**——支持任意分辨率输入，NaViT 风格的处理方式 |
| 核心改进 | (1) 视频理解——输入多帧图像（视频采样），支持跨帧推理；(2) 多语言 OCR——中英双语文字识别能力突出 |
| 影响 | 开源 VLM 中综合能力最强之一 |

### 2024.09 — LLaMA 3.2-Vision（Meta）· ✅ 开源

| 维度 | 说明 |
|------|------|
| 架构 | CLIP ViT + LLaMA 3.1（11B / 90B）|
| 核心改进 | **Meta 第一次将视觉能力融入 LLaMA 系列**。90B 版本是当时最大的开源 VLM |
| 影响 | 标志着"主流 LLM 厂商把视觉能力作为标配" |

### 2024.10 — Emu3（BAAI）· ✅ 开源

**"Emu3: Next-Token Prediction is All You Need"（Sun et al., 2024）**

| 维度 | 说明 |
|------|------|
| 架构 | **纯 Decoder-only + 离散 token（MoVQGAN）**——文本、图像、视频都在同一 token 空间 |
| 核心改进 | **(1) 统一架构——文本和图像共享同一个 tokenizer 和同一个 Transformer**；(2) 真正的原生多模态——不需要 CLIP、不需要视觉编码器、不需要连接器，一切是 token 序列 |
| 参数量 | 7B |
| 意义 | 证明了"用 next-token prediction 也能做图像生成和理解"。多模态领域的"Transformer 时刻"——一个架构统一所有任务 |

```
Emu3 的"纯 token"路线:

  文本: "Hello" → BPE token → [125, 34, ...]
  图像: 像素 → MoVQGAN → 离散 token → [8921, 441, ...]
  
  所有 token 输入同一个 Transformer:
    ┌─────────────────────────────────┐
    │     Transformer (Decoder-only)   │
    │     next-token prediction        │
    │     "所有 token 一视同仁"         │
    └─────────────────────────────────┘

  训练: 图文交错的 token 序列 → 预测下一个 token
  推理: 给一个图像 token 序列 → 生成文本描述
        给一段文本 → 生成图像 token 序列 → VQ Decoder → 图像

优势: 架构极简，不需要 CLIP / Q-Former / MLP Projector
挑战: VQ tokenizer 的压缩/重建质量、长序列计算成本
```

### 2024.12 — Gemini 2.0（Google DeepMind）· ❌ 闭源

| 维度 | 说明 |
|------|------|
| 核心改进 | **多模态输出**——除了理解，还能生成图像和语音。内置原生工具调用和 Agent 能力 |
| 意义 | 多模态大模型从"看懂说好"进化到"能做事情" |

### 阶段总结

```
第五阶段的贡献:
  - 动态分辨率打破 ViT 的 224² 天花板
  - 视频理解从"帧拼接"到"真正的多帧时序处理"
  - GPT-4o 实现了 real-time 音频+视觉+文本的全模态融合
  - Emu3 证明了"纯 token 统一架构"的可行性

核心局限:
  1. 视频时序建模仍是帧拼接——没有真正的"视频理解"因果推理
  2. 架构方案未收敛——LLM-first（LLaVA）vs 原生多模态（Gemini）vs 纯 token（Emu3）
  3. 幻觉问题——VLM 对空间关系、数量、属性绑定的系统性幻觉
  4. 训练成本指数级上升——顶尖模型数万 GPU 小时起步
```

## 第六阶段：统一理解 + 生成 + Agent（2025-2026）——"全能模型时代"

- **理解与生成的统一**——传统 VLM 只能输出文本，但 GPT-4o / Gemini 2.0 已能输出图像

## 六大核心技术演变总结

| 维度 | 浅层融合（2015-2018）| 跨模态 Transformer（2019-2020）| 对比学习（2021-2022）| 连接器 VLM（2023-2024 初）| 原生多模态（2024-2026）|
|------|----------------|------------------------|----------------|-----------------|----------------|
| **视觉编码器** | CNN（VGG/ResNet）| Faster R-CNN 区域特征 | CLIP ViT | CLIP ViT（冻结）| ViT（端到端训练）|
| **文本编码器** | RNN/LSTM | BERT 风格 Transformer | CLIP Text Encoder | LLM（冻结/微调）| LLM（全参数训练）|
| **融合方式** | 浅层拼接/注意力 | Co-Attention / Cross-Attn | 双塔对比（无融合）| MLP / Q-Former / Cross-Attn | 统一 token / 深层 Cross-Attn |
| **预训练数据** | COCO 120K | CC 3M | WIT 400M / ALIGN 1.8B | LAION / 指令数据混合 | 万亿 token 级 |
| **分辨率** | 固定 224² | 区域特征（固定）| 固定 224² | 224² ~ 336² | 动态～4K |
| **输入模态** | 单图+文本 | 单图+文本 | 单图+文本 | 单图/多图+文本 | 图+文+音频+视频 |
| **输出** | Caption / Answer | Answer | Image Embedding | 文本 | 文本+图像+语音 |

## 六大模型家族一览

```
CLIP 家族（视觉编码器生态）:
  2021 CLIP 400M → ALIGN 1.8B → SigLIP → EVA-CLIP → MetaCLIP
  路线: 对比学习双塔越来越大，成为所有 VLM 的视觉基础
  ❗ CLIP 不是完整的 VLM——它只做"编码对齐"，不做生成

Flamingo → BLIP-2（桥接路线）:
  2022 Flamingo 80B（Gated Cross-Attn）→ 2022 BLIP-2（Q-Former）
  路线: Frozen ViT + 可学习连接器 + Frozen LLM
  被 LLaVA 的 MLP Projector 路线取代

LLaVA 家族（开源 VLM 事实标准）:
  2023 LLaVA 7B → 2024 LLaVA-1.5 13B → LLaVA-NeXT → 2025 LLaVA-OneVision 8B
  路线: CLIP ViT + MLP Projector + LLM，从 Vicuna → LLaMA → Qwen
  ✅ 最简单、最广泛的 VLM 架构

Qwen-VL 家族（阿里，开源）:
  2023 Qwen-VL 7B → 2024 Qwen2-VL 72B → 2025 Qwen2.5-VL 72B → Qwen3-VL MoE
  路线: ViT + Qwen LLM，双语（中英），视频支持不断增强
  ✅ 最强的中英文开源 VLM 系列

InternVL 系列（上海 AI Lab，开源）:
  2024 InternVL 1.5 20B → InternVL 2.0 40B → 2025 InternVL 3.0 78B → InternVL 3.5 241B
  路线: 超大 ViT（6B）+ LLM 端到端训练
  ⚡ 当前参数规模最大的开源 VLM（241B）

闭源商业模型:
  2023 GPT-4V → 2024 GPT-4o（Omni）→ 2025 o3/o4-mini（推理+视觉）
  2023 Gemini 1.0 → 2024 Gemini 1.5 Pro → Gemini 2.0 → 2025 Gemini 2.5 Pro → Gemini 3.0
  ❌ 闭源，但在能力和体验上始终领先开源
```

## 总结：十年的范式演变

| 时期 | 核心问题 | 代表 | 驱动力量 |
|------|---------|------|---------|
| 2015-2018 | 能不能让 AI 看图说话？ | Show and Tell, VQA, Bottom-Up Attention | CNN + RNN 的技术组合 |
| 2019-2020 | BERT 的范式能不能用在多模态？ | ViLBERT, LXMERT, UNITER | 跨模态 Transformer 预训练 |
| 2021-2022 | 能不能不做目标检测也能理解图？ | CLIP, ALIGN, Flamingo, BLIP-2 | 对比学习 + Frozen LLM |
| 2023-2024 初 | 能不能让 LLM 看图？ | LLaVA, GPT-4V, Qwen-VL | LLM 大爆发 + 指令微调 |
| 2024 | 能不能端到端、高分辨率？ | InternVL, Qwen2-VL, GPT-4o | 动态分辨率 + 原生多模态 |
| 2025-2026 | 能不能同时理解和生成、输出所有模态？ | Qwen-Omni, Emu3.5, Gemini 3.0 | Omni-Modal I/O + MoE |

> **多模态领域的竞争已从"能不能连起来"变成"连得多深、多模态、多高效"。** 三个核心方向——理解+生成统一、Omni 全模态、MoE 高效推理——将定义未来三到五年的赢家。
