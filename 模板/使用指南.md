# 使用指南：如何构建一个领域知识学习系统

## 一、整体工作流

```
第 1 步：画出全景图
    ↓
第 2 步：正交维度分解 → 创建 N 个子模块
    ↓
第 3 步：梳理范式跃迁 → 填入演进表格
    ↓
第 4 步：规划学习路径 → 针对目标用户定制顺序
    ↓
第 5 步：精选核心论文 → 每模块 2-5 篇并写阅读指导
    ↓
第 6 步：写每个子模块的正文 → 遵循子模块模板结构
    ↓
第 7 步：汇总论文总览 + 标注边界
```

## 二、关键设计原则

### 1. 正交分解原则

模块之间必须**互不重叠**。判断方法：如果你发现两个模块都在回答同一个问题，说明需要合并或重新划分。每个模块应有**唯一的核心问题**。

### 2. 叙事驱动原则

不要按时间顺序罗列技术，而是用 **"解决问题 → 留下麻烦 → 催生下一范式"** 的链条来组织。让每个技术节点的出现"有道理"——读者能理解"为什么必须有它"。

### 3. 个人化原则

同一份知识库可以服务不同背景的用户。在根目录用 **"你已经熟悉的 vs 你需要补齐的"** 对照表 + **定制学习顺序**来适配。不要假设读者从 01 开始读到 06。

### 4. 可验证目标原则

每个模块的"学习目标"必须用**可检验的行为动词**：

| ✅ 好的描述 | ❌ 不好的描述 |
|-----------|-------------|
| 能画出 X 的计算链路 | 理解 X 的原理 |
| 用一句话说清 A 和 B 的区别 | 掌握 A 和 B |
| 面对 X 项目能给出选 Y 的决策 | 了解 Y 的应用场景 |
| 能画出 A 到 B 的演进时间线 | 熟悉 A 到 B 的发展 |

### 5. 论文极简原则

整个领域的核心论文控制在 **15-25 篇**。每篇必须有明确的**阅读指导**（读哪里、跳过哪里、为什么读它）。宁缺毋滥——多一篇论文就多一份认知负担。

筛选标准：
- **突破性论文**：提出新范式的第一篇
- **验证性论文**：证明理论在工业/真实数据上可行的第一篇
- **奠基性论文**：被后续所有工作引用的标准
- **综述论文**：帮助建立领域全景

### 6. 边界透明原则

最后一个模块必须标明 **"当前仍然没有解决的问题"**。这有两个作用：
① 让学习者知道领域的局限，不盲目乐观
② 为学习者提供潜在的研究方向

### 7. 对比表格优先原则

任何有"选择"的地方，都用**对比表格**而非段落描述：

```
| 维度 | 方案A | 方案B | 方案C |
|------|-------|-------|-------|
| 优点 | ...   | ...   | ...   |
| 代价 | ...   | ...   | ...   |
| 适用场景 | ... | ... | ... |
```

一段话描述三个选项，读者读完也记不住；一个表格，扫一眼就清晰。

## 三、目录结构约定

```
领域名称/
├── README.md              ← 全景图 + 学习路径 + 范式演进 + 论文总览
├── 子模块模板.md           ← 子模块写作模板（选填，供协作使用）
│
├── 01-模块一名称/
│   ├── README.md          ← 模块正文
│   ├── 拓展/              ← 拓展论文（选填）
│   │   ├── 论文标题-年份.md
│   │   └── ...
│   └── 笔记/              ← 个人学习笔记（选填）
│
├── 02-模块二名称/
│   ├── README.md
│   └── ...
│
├── 03-模块三名称/
├── 04-模块四名称/
├── 05-模块五名称/
└── 06-模块六名称/
```

模块编号有两层含义：
- **推荐阅读序号**：默认按此顺序学习
- **逻辑分组**：01-04 是核心基础，05-06 是进阶

如果两个模块没有依赖关系，可以标注为"并行可读"。

## 四、完整性检查清单

- [ ] 能用一句话说清该领域的核心问题
- [ ] 每个模块有唯一的、不重叠的核心问题
- [ ] 范式演进表能追溯到 6 个以上的跃迁节点
- [ ] 每篇论文有明确的阅读指导（不是简单罗列）
- [ ] 有基于用户背景的定制学习路径
- [ ] 总论文数控制在 15-25 篇核心 + 5-10 篇拓展
- [ ] 标注了当前仍然 open 的挑战和边界
- [ ] 每个模块的学习目标是可检验的（"能画出"而非"理解"）
- [ ] 关键选择点有对比表格或决策树
- [ ] 有"解决了什么 + 留下了什么麻烦"的叙事框架

## 五、7 步生成清单

### 第 1 步：定义领域范围

```
领域名称：
领域英文名：
一句话描述：
目标用户画像：
知识库预计覆盖的时间跨度：
```

### 第 2 步：分解正交模块

列出 4-6 个独立问题，每个问题对应一个模块。验证方法：如果能用"你已经有 A 的知识也没有帮助理解 B"来说明两个模块相对独立，就算通过。

### 第 3 步：梳理范式演进

列出该领域经历的重大范式变迁，每个范式写一个"解决了什么 + 留下了什么麻烦"的对偶描述。确保链条首尾相连——范式 N 的麻烦恰好是范式 N+1 在解决的问题。

### 第 4 步：精选核心论文

每个模块选择 2-5 篇核心论文。对每篇论文写清楚：
① 一句话定位
② 阅读重点
③ 时间分配建议

筛选优先级：突破性 > 验证性 > 奠基性 > 综述。

### 第 5 步：设计学习路径

基于目标用户已有的知识来设计学习顺序，而不是按模块编号顺序。用"你熟悉的 vs 你需要补的"对照表来建立学习者的自我认知。

### 第 6 步：撰写子模块

每个子模块遵循：开场问题 → 渐进式正文（5 层深度）→ 学习目标 → 精选论文 → 拓展阅读 → 模块间连接。

### 第 7 步：汇总与校验

填写论文总览表格，标注当前前沿问题，最后用完整性检查清单过一遍。
