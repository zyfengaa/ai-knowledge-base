## 写在前面

2025 年中，有两件事困扰着整个 LLM 社区：

1. **训练万亿 MoE 就像走钢丝**——DeepSeek-V3 证明了 MoE + MLA 的路能走通，但任何人想自己训万亿参数模型，都要面对 loss spike（损失尖峰）、专家坍缩、训练不稳定这些噩梦。训练几十亿参数的模型已经很难了，再往上规模扩大 10 倍，稳定训练几乎靠玄学。

2. **"智能体能力是后加的"**——所有模型都是先训一个语言模型，再想方设法给它加工具调用、加代码执行、加多轮交互。智能体不是模型的一部分，是事后贴在模型上的补丁。

2025 年 7 月，月之暗面（Moonshot AI）的 **Kimi K2** 一次性解决了这两个问题：
- **1.04T 参数**的 MoE，从头训到尾 **零个 loss spike**
- **原生智能体能力**——工具调用、代码执行、多轮交互直接内建在预训练和 RL 阶段

## 第一章 前置条件：MoE 训练的噩梦和智能体的缺口

### 1.1 MoE 的稳定性问题

混合专家模型（Mixture of Experts, MoE）用一组"专家"子网络代替单个 FFN，理论上可以在不显著增加计算量的情况下扩大模型容量：

```
MoE 前向计算（路由）:
  g(x) = softmax(TopK(W_g · x))     ← 路由器给每个专家打分
  y = Σ_g_i(x) · E_i(x)              ← 只有 Top-K 个专家被激活
```

但实际训练中是另一回事：

1. **Loss Spikes（损失尖峰）**——训练过程中损失突然暴跳 10-100 倍，然后可能恢复、也可能直接发散。在大规模训练中，一次 loss spike 可能毁掉几千 GPU 小时的算力。

2. **专家坍缩（Expert Collapse）**——路由器把几乎所有 token 路由到少数几个专家，其他专家"饿死"——根本不学习。

3. **负载不平衡（Load Imbalance）**——少数专家过载、多数专家闲置，硬件利用率极差。

```
常见的 MoE 训练问题模式:

Loss ↑
  |         ▁▁▁▁▁▁▁▁▁▁▆█████████▁▁▁▁▁▁▁▁
  |                        ↑         ↑
  |                    loss spike    可能发散
  └─────────────────────────────────────→ Steps
```

即使 DeepSeek-V3 用 aux-loss 做负载均衡、用细粒度专家分配缓解坍缩，这些问题在大规模训练中仍然是常态。

### 1.2 智能体能力的"后贴"困境

2025 年之前的智能体模型通常走三步：

```
第一步: 预训练一个纯语言模型（GPT/Llama/Qwen...）
第二步: SFT 微调，注入指令遵循能力
第三步: 再微调，加入工具调用、代码执行等智能体能力
```

问题很清晰：

- 智能体能力是**附加的**，不是模型本身的一部分。训练时"这个括号是函数调用参数"和"这个括号是中文标点"在模型看来毫无区别
- 工具调用的格式、逻辑、错误处理——模型需要在后训阶段**从零学起**，没有任何预训练的先验知识
- 多轮交互中的状态追踪、工具调用之间的依赖关系——这些对纯语言模型来说完全是新的任务类型

**Kimi K2 的回答是：智能体能力在预训练阶段就内建。不需要后贴——它生来就是智能体。**

## 第三章 Kimi K2：整体架构（2025 年 7 月，MIT 开源）

### 3.1 完整模型配置

| 参数 | 值 |
|------|-----|
| 总参数量 | **1.04T**（1,040,000,000,000） |
| 每 Token 激活参数 | **32B** |
| 层数 | 61（1 层密集 + 60 层 MoE） |
| 总专家数 | **384** |
| 每 Token 激活专家 | **8 + 1 共享专家** |
| 稀疏比 | **48:1**（384/8） |
| 注意力机制 | **Multi-Head Latent Attention (MLA)** |
| 注意力头数 | 64 |
| 隐藏维度（d_model） | 7,168 |
| 专家隐藏维度（d_ff） | 2,048 |
| 词汇表大小 | 160K |
| 上下文长度 | 128K |
| 训练数据 | 15.5T token |
| 优化器 | **MuonClip**（本文核心创新之一） |
| 开源协议 | MIT |

### 3.2 架构总览

```
Kimi K2 整体架构示意:

输入 Token → [嵌入层 (160K vocab → 7168 dim)]
    │
    ├── Layer 0: 密集层 (Dense FFN + MLA)
    │
    ├── Layer 1~60: MoE 层 (每个 384 专家, 激活 8 + 1 共享)
    │   ┌──────────────────────────────┐
    │   │  Step 1: MLA (64 头, 潜空间) │
    │   │  Step 2: RMSNorm             │
    │   │  Step 3: MoE FFN             │
    │   │     └─ 路由器 → Top-9 (8+1)   │
    │   │     └─ SwiGLU 门控激活       │
    │   │  Step 4: 残差连接             │
    │   └──────────────────────────────┘
    │
    └── 输出 → [解码器 + softmax] → 下一个 token 概率
```

### 3.3 MLA（Multi-Head Latent Attention）——潜空间压缩注意力

K2 的 MLA 与 DeepSeek-V3 采用同样的设计——将 KV Cache 压缩到潜空间，大幅降低推理显存：

```
标准 MHA vs MLA 的 KV Cache 对比:

标准多头注意力 (MHA):
  每层存储: K [n_layers, n_heads, seq_len, d_head] ≈ 全尺寸
  显存 = O(n_layers · n_heads · seq_len · d_head)

MLA (潜空间压缩):
  不直接存储 KV，而是存储它们的低维潜表示:
  c_kv = W_DKV · concat(K, V)    ← 压缩到潜空间
  K' = W_UK · c_kv               ← 解压缩回原维度
  V' = W_UV · c_kv

  显存 = O(n_layers · d_latent · seq_len)  ← 压缩率 4-6x
```

**K2 对 MLA 的配置不同于 DeepSeek-V3：**

| 差异点 | DeepSeek-V3 | Kimi K2 |
|--------|-------------|---------|
| 注意力头数 | **128** | **64** |
| 潜空间维度 | 576 | 较低（未公开具体值） |
| QK-Norm | 无 | 无（MLA 不需要，因为 key 不被具体化） |

为什么 K2 只用 64 个头（DeepSeek 的一半）？

```
64 heads × 7168 dim → 每个 head 112 维
128 heads × 7168 dim → 每个 head 56 维

K2 的选择:
  - 更少的头 → 每个头维度更大 → 表达能力更强
  - 更少的头 → 注意力计算的矩阵尺寸更小 → 长序列推理更快
  - 牺牲一点注意力的多模式多样性，换取推理效率

权衡: K2 的长上下文（128K）场景下，更少的头直接减少 KV Cache 和计算量
```

另一点：K2 **没有使用 DeepSeek-V3 的专家分组**。DeepSeek-V3 把专家分为多个组、每个组独立路由，设计来缓解专家坍缩。K2 认为一组 384 个专家不需要分组——因为有 MuonClip 控制训练稳定性，整体路由即可。

### 3.4 稀疏性的选择

K2 最引人注目的设计决策之一是**极端的稀疏性**：

```
DeepSeek-V3: 256 专家, 激活 8 → 稀疏比 32:1
         ↓ 增加 50% 专家
Kimi K2:  384 专家, 激活 8 → 稀疏比 48:1
```

月之暗面通过 Scaling Law 实验验证了稀疏性的价值：

```
Scaling Law 实验结果（示意）:

验证损失
  ↓
  ██ 64 专家 ── 最高 loss
  ██ 128 专家 ── 中间
  ██ 256 专家 ── 更低
  ██ 384 专家 ── 最低 loss
  ██ 512 专家 ── 边际收益递减
  └─────────────────────→ 总参数量（固定激活参数）

结论:
  - 更多专家 = 更低的验证 loss（在相同激活参数下）
  - 384 是性价比最优的折中点
  - 超过 512 后收益递减（专家太稀疏，利用率下降）
```

**为什么 384 专家是甜点？**

- 每个专家 d_ff = 2048（相对较小），更多专家意味着更细粒度的知识分片
- 48:1 的稀疏比下，每个 token 只访问 1/48 的参数，计算效率极高
- 384 专家的负载均衡在小批量训练下仍然可控（配合 MuonClip）

## 第四章 MuonClip 优化器——零 Loss Spikes 的核心工程创新

### 4.1 从 AdamW 到 Muon

在深入 MuonClip 之前，先理解它的前身 **Muon 优化器**：

```
标准 AdamW 更新规则:
  m_t = β₁·m_{t-1} + (1-β₁)·g_t          ← 动量
  v_t = β₂·v_{t-1} + (1-β₂)·g_t²         ← 自适应学习率
  θ_t = θ_{t-1} - η · m_t / (√v_t + ε)   ← 逐元素更新

Muon 的核心思想:
  "把动量矩阵正交化。"

  1. 梯度 g_t 被组织为矩阵（而不是扁平的向量）
  2. 对矩阵应用 Newton-Schulz 迭代做正交化:
     Ortho(M) ≈ M · (I + M²·(I + M⁴·(I + ...))/2)/2
  3. 正交化后的梯度具有更好的条件数 → 优化路径更直

  关键论文: "Muon is Scalable for LLM Training" (Moonlight, 2025)
```

```
AdamW vs Muon 的优化路径对比（概念图）:

AdamW:
  每次更新的方向是逐元素归一化的梯度
  ▰ ▰ ▰ ▰ ▰
   ▰ ▰ ▰ ▰ ▰
    ▰ ▰ ▰ ▰ ▰      ← 每一步"修正"方向，震荡较多
     ▰ ▰ ▰ ▰ ▰
      ▰ ▰ ▰ ▰ ▰

Muon:
  每次更新前做矩阵正交化 → 路径更直
  ▰→▰→▰→▰→▰
     ↘
      ▰→▰→▰→▰    ← 接近"最速下降"的理想路径
         ↘
          ▰→▰→▰
```

**Muon 的优势**：在 Moonlight 实验中，Muon 用 1/2 的计算量达到了与 AdamW 相同的 loss。

**Muon 的问题**：纯 Muon 在大规模训练中仍然不稳定——尤其当注意力 logits 的值过大时，梯度爆炸的风险仍然存在。

### 4.2 MuonClip = Muon + QK-Clip

K2 对 Muon 做了三处关键改进：

```
MuonClip = Muon + Weight Decay + Consistent RMS Scaling + QK-Clip

1. Weight Decay (权重衰减):
   标准 AdamW 中的 L2 正则化，

2. Consistent RMS Scaling (一致的 RMS 缩放):
   保证 Muon 更新的均方根值与 AdamW 匹配，
   避免因正交化导致的更新量级漂移

3. QK-Clip (核心创新):
   对 Q 和 K 投影矩阵的每头输出做剪裁:
   If max Attention Logits > τ (τ=100):
       按比例缩放 Q 和 K 的投影权重
       直到最大 logits ≤ τ
```

**QK-Clip 的动机**：

```
注意力 logits 的分布与训练稳定性:

标准情况下:
  Q · Kᵀ / √d 的分布应该相对集中（方差 ≈ 1）

但大规模训练中:
  某些 head 的 Q 或 K 投影矩阵可能会"膨胀"
  → 注意力 logits 变得非常大（> 10³ ~ 10⁴）
  → softmax 输出接近 one-hot（一个位置接近 1, 其他 ≈ 0）
  → 梯度几乎为 0 → 训练停滞
  → 数值精度问题（float16/bfloat16 溢出）
  → Loss Spike!

QK-Clip 的工作原理:
  ┌────────── Query 和 Key 的每一头 ─────────┐
  │                                           │
  │  Step 1: 计算 Q_head · K_headᵀ / √d       │
  │  Step 2: 如果 max > τ (=100):              │
  │     │                                      │
  │     ├─ 缩放比例 = τ / max_logits           │
  │     ├─ W_Q_head = W_Q_head · √(缩放比例)   │
  │     ├─ W_K_head = W_K_head · √(缩放比例)   │
  │     └─ 重新计算 logits（确认 ≤ τ）         │
  │                                           │
  │  Step 3: 继续正常前向/反向传播             │
  │                                           │
  └── 注意: 不是梯度裁剪——是权重裁剪 ──────────┘
```

### 4.3 MuonClip 的训练稳定性

K2 的 15.5T token 训练全程没有出现一次 loss spike——这在万亿参数 MoE 训练中是罕见的成就：

```
标准 AdamW 训练 vs MuonClip 训练的 Loss 曲线对比:

Loss
│
│   AdamW（典型的大规模 MoE 训练）:
│   ▁▁▁▂▂▃▃▄▄▅▅▆▇██▇▆▅▄▃▂▁▁▂▃▄▅▆▇████▇▆▅▄▃▂
│                          ↑ loss spike        ↑ 另一次 spike
│                          恢复后 loss 更高    （可能发散）
│
│   MuonClip（Kimi K2）:
│   ▁▁▂▂▃▃▄▄▅▅▆▆▇▇██████████████████████████▇▇▆▆▅▅▄▄▃▃▂▂▁
│                          ↑ 一个 loss 尖峰都没有
│                          训练曲线平滑下降 → 完美收敛
└──────────────────────────────────────────────────────────→ Steps
```

### 4.4 MuonClip 与辅助损失的关系

一个值得注意的设计选择：K2 不使用 DeepSeek-V3 式的 **aux-loss（辅助负载均衡损失）**，也不需要 **专家偏置（expert bias）**：

```
为什么 MuonClip 不需要 aux-loss？

传统 aux-loss 的作用:
  - 在损失函数中加入惩罚项，鼓励路由器平均分配 token 到所有专家
  - 问题是: aux-loss 是"软约束"——它和主训练目标可能冲突
  - 强度超参难调: 太弱无效，太强损害模型质量

MuonClip 的隐式稳定性:
  - 当某个专家被过度使用时，它的参数更新幅度增大
  - 更新幅度增大 → QK-Clip 的剪裁更频繁 → 梯度信号被限制
  - 梯度的限制反过来抑制了对该专家的过度路由
  - 形成一种"负反馈"的自我调节机制

效果: 384 个专家在整个训练过程中保持相对均匀的负载，不需要人工干预
```

## 第五章 训练创新——不只是架构

K2 的训练数据策略同样值得关注，尤其是三个方面：

### 5.1 知识数据改写（Knowledge Data Rephrasing）

传统做法是把原始文本直接喂给模型训练。K2 的做法是**先改写，再训练**：

```
原始文本:
  "变压器是利用电磁感应原理来改变交流电压的装置..."

╲ 改写器（大语言模型） ╱

改写后的多个版本:
  版本 A (教科书风格):
    "变压器通过电磁感应改变交流电压..."

  版本 B (问答风格):
    "问: 变压器的作用是什么？答: 改变交流电压..."

  版本 C (比喻风格):
    "变压器就像电压的翻译器——把一种电压"翻译"成另一种..."

  版本 D (第一人称):
    "我是变压器。我被制造出来做一件事..."
```

**目的**：同一个知识以多种风格、多种视角呈现，让模型学到的是知识的**本质**而不是它的**表面形式**。

### 5.2 数学数据改写（Mathematics Data Rephrasing）

对于数学内容，K2 采用"学习笔记"风格改写：

```
原始数学题解:
  "设 f(x)=ax²+bx+c，由条件得 f(1)=0，因此 a+b+c=0..."

╲ 改写器 ╱

学习笔记风格:
  📌 关键思路: 利用 f(1)=0 建立方程
  ⚠️ 易错点: 注意 f(1) 代入的是 x=1，不是 x=0
  🧩 扩展: 也可以用 f(1)+f(2) 的形式构造函数

  Step 1: 写出二次函数一般形式 f(x)=ax²+bx+c
  Step 2: 代入 x=1 → f(1)=a+b+c=0  ← 这是关键方程
  Step 3: 同理代入其他条件联立求解
```

**效果**：模型不仅会算数学题，还学会了"把解题思路讲清楚"——这对数学推理的 Chain-of-Thought 能力至关重要。

### 5.3 智能体数据合成（Agentic Data Synthesis）

K2 智能体能力的来源——大规模工具使用数据的合成：

```
模拟环境中的智能体训练数据生成:

┌─────────────────────────────────┐
│          环境模拟器               │
│                                 │
│  ┌─────┐  ┌─────┐  ┌─────┐     │
│  │ Bash │  │ 代码 │  │ 网络 │     │
│  │终端  │  │解释器│  │搜索 │     │
│  └──┬──┘  └──┬──┘  └──┬──┘     │
│     │        │        │         │
│  ───┴────────┴────────┴──       │
│        任务生成器                │
│  "计算日志文件中的错误率"        │
│  "在 GitHub 上创建 PR"          │
│  "查询数据库并按日期聚合"        │
└─────────────────────────────────┘
         │
         ▼
  ┌──────────────────┐
  │  工具调用轨迹     │
  │                   │
  │  [用户请求]        │
  │  [思考] "我需要…"  │
  │  [调用] bash ls    │
  │  [输出] file1.txt  │
  │  [思考] "然后…"    │
  │  [调用] python ... │
  │  [输出] 结果       │
  │  [回答] "结论是…"  │
  └──────────────────┘
```

**与传统方法的关键区别**：
- 传统：用人类标注的少量工具调用示例做 SFT → 模型只是"记住了格式"
- K2：在模拟环境中生成**海量**工具调用轨迹 → 模型学会了"工具调用的通用逻辑"，而不仅限于格式

### 5.4 联合强化学习（Joint RL）

K2 的强化学习阶段使用了**两套奖励信号**：

```
Joint RL 的奖励框架:

每个 token 生成后:

奖励信号 1: 可验证奖励 (Verifiable Rewards)
  └── 代码执行是否通过测试？✓/✗
  └── 数学答案是否正确？✓/✗
  └── 工具调用结果是否符合预期？✓/✗
  └── 这是"硬信号"——对错分明

奖励信号 2: 自我批评评价 (Self-Critique Rubric)
  └── 模型生成一个回答后，再对自己写一个评价:
      "我的回答是否完整？是否遗漏了重要信息？"
      "我选择的工具是否正确？有没有更好的方案？"
  └── 这是"软信号"——注重过程质量

联合训练:
  L_total = α·L_verifiable + β·L_self_critique
  模型同时从"对错"和"好坏"中学习
```

**效果**：K2 在 SWE-bench Verified 上达到 65.8%——这是当时开源模型的最高记录。

## 第七章 Kimi K2.5：升级到原生多模态（2026 年 1 月，MIT 开源）

K2.5 是 K2 的多模态升级版——不是"语言模型 + 视觉模块"的拼接，而是**原生视觉-语言融合**。

### 7.1 K2 vs K2.5 架构对比

```
K2（文本专用）:                         K2.5（视觉-文本融合）:

输入: Token 序列                     输入: Token + 视觉 Token
      "今天天气真好"                       [IMG] 图片 [IMG] "描述这张图"
      │                                    │
      ▼                                    ▼
  文本嵌入层                          文本嵌入层 + MoonViT 视觉编码器
      │                                    │
      ▼                                    ▼
  文本 Token 流                       早期融合: 10% 视觉 : 90% 文本
      │                                    │
      ▼                                    ▼
  61 层 Transformer                  61 层 Transformer（参数共享）
      │                                    │
      ▼                                    ▼
  文本输出                            文本 + 视觉输出
```

**关键设计点：早期视觉-文本融合**：

```
早期融合 vs 后期融合:

后期融合（典型 VLM: LLaVA、Qwen-VL）:
  [文本 Token] → [LLM...] → [文本输出]
                             ↑
  [视觉编码] → [投影层] ────┘
  
  问题: 视觉信息只在输入层融合一次 → LLM 的深层看不到图像

早期融合（K2.5）:
  [文本 Token] → [投影]
                  ↓
  [视觉 Patch] → [投影] → [混合 (10%视觉:90%文本)]
                           ↓
  [LLM ... 每层都看到视觉和文本 Token 混合在一起]
                           ↓
                       [输出]

  优势:
    - 每层 Transformer 都可以参考视觉信息
    - 视觉-文本交互更自然（"这张图的左上角和文字描述的第三句矛盾"）
    - 不需要复杂的视觉投影层——视觉 Token 直接被当成一种"特殊语言"
```

### 7.2 Zero-Vision SFT

K2.5 有一个反直觉的现象：**纯文本 SFT 数据也能激活视觉推理能力**。

```
Zero-Vision SFT 的工作原理:

SFT 阶段使用的数据:
  ┌──────────────────────────────────────┐
  │ 纯文本 SFT 样本（占 30%）:            │
  │   "总结这篇文章的要点..."             │
  │   "用 Python 实现二分查找..."         │
  │   "翻译以下内容到中文..."             │
  └──────────────────────────────────────┘
  
  ┌──────────────────────────────────────┐
  │ 视觉 SFT 样本（占 0%）:               │
  │   ———— 完全没有 ————                 │
  └──────────────────────────────────────┘

结果: 视觉推理一样被激活——为什么？
  
原因推测:
  - 视觉 Token 在预训练时就已见过
  - SFT 阶段用纯文本数据"教会模型如何组织回答"
  - 这种回答组织能力自动迁移到视觉场景
  - 说明: 视觉理解和语言表达能力的分离是可实现的
```

这是一个对未来多模态训练有深远影响的发现——也许你不需要大量的多模态 SFT 数据，只要预训练阶段做好了视觉-文本对齐，SFT 阶段纯文本数据就够用。

### 7.3 Agent Swarm——多智能体协作框架

K2.5 引入了 **Agent Swarm** 框架：

```
Agent Swarm 架构示意:

用户请求: "分析这份财报，做一个 PPT 摘要，发邮件给团队"

         ┌─────────────────────────────────────┐
         │         编排器 (Orchestrator)        │
         │   理解意图 → 分解任务 → 分发 → 汇总  │
         └──┬────┬────┬────┬────┬────┬────┬──┘
            │    │    │    │    │    │    │
            ▼    ▼    ▼    ▼    ▼    ▼    ▼
         ┌─────────────────────────────────────┐
         │  Agent Pool                         │
         │  ┌──────┐ ┌──────┐ ┌──────┐        │
         │  │搜索  │ │代码  │ │读取  │        │
         │  │Agent │ │Agent │ │文件  │        │
         │  └──────┘ └──────┘ └──────┘        │
         │  ┌──────┐ ┌──────┐ ┌──────┐        │
         │  │PPT   │ │邮件  │ │分析  │        │
         │  │Agent │ │Agent │ │Agent │        │
         │  └──────┘ └──────┘ └──────┘        │
         └─────────────────────────────────────┘

Agent 之间的通信:
  [搜索 Agent] → "财报链接已找到，文件已下载至 /tmp/report.pdf"
  [分析 Agent] → "从财报中提取了 5 个关键指标..."
  [PPT Agent] → "已按照模板生成 10 页 PPT"
  [邮件 Agent] → "邮件已发送至 team@company.com"
```

## 第八章 Moonlight——Muon 优化器的实证基础

要理解 K2 为什么敢用 MuonClip，得先看它前面的 **Moonlight**（2025 年 2 月）。

### 8.1 模型配置

| 参数 | 值 |
|------|-----|
| 总参数量 | 15.29B（MoE） |
| 激活参数 | **2.24B** |
| 训练数据量 | 5.7T token |
| 优化器 | **Muon**（MuonClip 的前身） |
| 计算效率 | AdamW 的 **2 倍** |

### 8.2 核心发现

```
Moonlight 的核心结论:

在固定计算预算下（相同 FLOPs）:

损失
│
│   AdamW: ▁▂▃▃▄▅▆▇███▇▆▅▄▃▃▂▁
│   Muon:  ▁▂▃▃▃▄▅▆▇█████▇▆▅▄▃▂  ← 在相同 FLOPs 下 loss 更低
│
│   达到相同 loss 所需的 FLOPs:
│   Muon = AdamW × 55%
│      ↑ 也就是 Muon 用 AdamW 一半多的算力就能达到同等效果
│
└──────────────────────────────→ FLOPs

另一个关键发现:
  - Muon 在从头训练中表现出色（从随机初始化开始）
  - 但 Muon 在续训（继续训练已有模型）中不稳定
  - 这催生了 K2 中 MuonClip 的改进
```

Moonlight 的实验结果为 K2 的优化器选择提供了坚实的 Scaling Law 级别的证据——Muon 系列优化器在大规模训练中是可行的。

## 第九章 Attention Residuals——残差连接的革新（2026 年 3 月）

这是 K2/月之暗面序列中目前最新的工作——尝试修改自 2017 年 Transformer 论文以来从未被质疑过的残差连接设计。

### 9.1 标准残差连接的问题

```
Transformer 的经典残差连接:

  LayerOutput = x + Sublayer(x)
                  ↑
              固定加法 ("skip connection")

  每层的输入都来自: 上一层输出 + 当前子层输出
  
  问题是:
    - 信息流是"链式"的——第 n 层只能看到第 n-1 层的输出
    - 深层的语义信息无法直接"跳回"浅层
    - 每一层都只能从上一个邻居获取信息
```

### 9.2 Attention Residuals 的改进

```
标准残差:                             Attention Residuals:

x_{l+1} = x_l + FFN(x_l)            x_{l+1} = Σ α_{l,i} · x_i + FFN(x_l)
            ↑  只来自上一层的输入                ↑  来自所有前层，加权选择

输入的来源:
  ┌─── Layer 1 ───┐               ┌─── Layer 1 ────────────────────────┐
  │ 输出 → Layer 2│               │ 输出 → Layer 2, Layer 3, ...      │
  └────────────────┘               └───────────────────────────────────┘
                                   ┌─── Layer 2 ────────────────────────┐
  ┌─── Layer 2 ───┐               │ 输入 = α₁·Layer1_Output +          │
  │ 输入 = L1_Out │               │        α₀·Layer0_Output + FFN(L2)  │
  │ 输出 → L3     │               │ ← 选择性聚合前两层的输出            │
  └────────────────┘               └───────────────────────────────────┘

关键: 每个 Layer l 有一个可学习的"注意力向量"{α_l,0, α_l,1, ..., α_l,l-1}
      决定从前面的每一层获取多少信息。
      注意力的计算方式 —— 本身就是一个 tiny attention:
      α_{l,i} = softmax(q_l · k_i / √d)   其中 q_l, k_i 是线性投影
```

### 9.3 效果

```
Attention Residuals 在 Kimi Linear 48B 上的效果:

评测                Baseline  +AttnRes  提升幅度
─────────────────────────────────────────────
GPQA              基准值      +7.5      显著
MATH              基准值      +3.6      稳定
HumanEval         基准值      +3.1      稳定

Block AttnRes (应用到所有层) 等效于:
  在计算量增加 25% 的情况下，获得约 1.5 倍的训练效益

高层结论:
  - 浅层 → 深层的信息通路对表达能力的提升比预期大得多
  - 残差连接的"固定加法"自 2017 年以来几乎没有被质疑过
  - Attention Residuals 是第一个严肃尝试修改这一设计的方案
```

Attention Residuals 发布后引起了不小的关注：
