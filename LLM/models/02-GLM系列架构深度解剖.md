# GLM 系列架构深度解剖

> 智谱AI（Zhipu AI） | "General Language Model Pretraining with Autoregressive Blank Infilling" —— 中国大模型中最具架构辨识度的路线

---

## 写在前面

2021 年，当 GPT-3 的 Decoder-only 路线如日中天、BERT 的 Encoder-only 路线仍占据理解类任务半壁江山时，智谱AI 与清华 KEG 实验室共同提出了 GLM（General Language Model）：

> **"不要选边站。理解和生成本来就该是同一个模型的两种能力——用自回归填空训练一个 Encoder-Decoder 混合体。"**

这一刀切得有多特别——GLM 不做纯 Encoder（BERT）、也不做纯 Decoder（GPT），而是做了一个 **Encoder-Decoder 混合架构**，用 **自回归空白填充（Autoregressive Blank Infilling）** 统一了理解与生成。从 GLM-10B（2021）到 GLM-5.2（2026），这条路线走了五年。

智谱AI 也是中国第一个上市的 LLM 公司（2026 年 1 月，港交所）。GLM-5.2 在 2026 年中保持全球开源大模型智能指数 **#1（51 分）**。国产芯片全栈适配（昇腾、摩尔线程、寒武纪）是它的另一张王牌。

## 第一章 前置条件：GPT 与 BERT 的路线之争

### 1.1 大模型时代的两种训练范式

在理解 GLM 之前，需要先理解它要解决的问题：

```
GPT 路线（Decoder-only）:
  训练目标: 下一个词预测（Next Token Prediction）
  注意力:  因果掩码（每个位置只能看左边）
  擅长:    生成 → 文本续写、对话、代码
  不擅长:  需要双向理解的分类/NER → 能力较弱

BERT 路线（Encoder-only）:
  训练目标: 掩码语言模型（Masked LM）
  注意力:  双向（每个位置看到全部）
  擅长:    理解 → 分类、标注、句子关系判断
  不擅长:  生成 → 需要额外 Decoder 或非自回归策略
```

**核心矛盾**：一个模型能不能既理解得好又生成得好？

- 纯 Decoder：生成天然，但理解时只有因果注意力，看不到"下文"
- 纯 Encoder：理解天然，但生成时需要构造额外的解码结构
- T5 方案：完整的 Encoder + Decoder，但两套参数，计算量大

**GLM 的核心 insight**：如果训练目标本身就能同时要求双向理解和单向生成，那一个模型就够了。

### 1.2 为什么"统一"这么难

理解任务要求**双向上下文**（一段话的感情色彩可能需要看最后一个词才能确定），生成任务要求**单向顺序**（生成时你不能看到未来的词）。这两个需求在注意力机制层面是**互斥的**：

```
理解任务: "这家餐厅的菜品[    ]好吃。"
          需要看"好吃"来判断填空的词性 → 需要双向

生成任务: "这家餐厅的菜品"
          需要逐个预测后续词 → 需要因果
```

GLM 的解决思路：**同一个模型，填空部分用因果生成，上下文部分用双向编码。** 问题不在于架构不能同时做两件事，而在于训练目标没有这样要求。

## 第二章 GLM 架构核心：自回归空白填充

GLM 最核心的创新在训练目标，而非基础架构本身。

### 2.1 目标定义

自回归空白填充的策略如下：

```
输入文本: "我今天[MASK]车去[MASK]上班。"
                    ↓
分割成两块:
  上下文 (Context):  "我今天 车去 上班。"  ← 保留可见的文本
  空白 (Blank):      ["开着", "公司"]      ← 被遮住的部分
                    ↓
输入模型:
  Part A (被破坏的文本):  "我今天 车去 上班。"
  Part B (空白内容):      "[MASK] [MASK]"  ← 在 Part A 末尾拼接
                    ↓
模型处理:
  - Part A 的所有位置 → 双向注意力（能看到彼此）
  - Part B 的所有位置 → 因果注意力（只能看 Part A + 之前生成的 Part B 位置）
  - Part B 中的第一个词能看到 Part A 全部，第二个词能看到 Part A 全部 + 第一个词
                    ↓
损失: 只在 Part B（空白部分）计算交叉熵
      每个空白位置按顺序自回归预测
```

### 2.2 BERT vs GPT vs GLM 训练对比

```
BERT (Masked LM):
  输入: "I [MASK] to the [MASK] by car."
         ↓  双向注意力  ↓
  输出: 同时预测 "went" 和 "store"
         (两个位置的预测独立并行)
  特点: ✅ 理解好 / ❌ 不能生成连贯文本

GPT (Causal LM):
  输入: "I went to the store by car."
         ↓  因果注意力  ↓
  输出: 依次预测 "went" "to" "the" "store" "by" "car" "."
         (每个位置只看到左边的词)
  特点: ✅ 生成好 / ⚠️ 理解弱（看不到下文）

GLM (Autoregressive Blank Infilling):
           ┌─────────────────────────────┐
           │  Part A: "I [MASK] to the    │
           │           [MASK] by car."    │ ← 双向注意力
           ├─────────────────────────────┤
           │  Part B: "[   went   ]"      │ ← 因果（只看 Part A）
           │           [   store  ]"      │ ← 因果（看 Part A + "went"）
           └─────────────────────────────┘
  特点: ✅ 理解好（Part A 双向编码）
        ✅ 生成好（Part B 自回归预测）
        ⚠️ 架构复杂度更高
```

### 2.3 与 BERT 的 Masked LM 的本质差异

| 维度 | BERT | GLM |
|------|------|-----|
| 预测方式 | 独立预测 —— 所有 [MASK] 同时输出 | **自回归预测** —— 按顺序逐词生成 |
| 对掩码词的建模 | 相互独立，看不到彼此 | 能看到之前已生成的掩码词 |
| 生成能力 | ❌ 无法做文本生成 | ✅ 天然支持文本生成 |
| 理解能力 | ✅ 自然 | ✅ 同样自然（Part A 双向） |
| 预训练-微调一致性 | ⚠️ 微调时没有 [MASK] token，有 gap | ✅ 微调时以生成方式适配，无 gap |

**关键 insight**：BERT 把填空当成"分类问题"——每个 [MASK] 独立分类；GLM 把填空当成"生成问题"——从左到右依次生成被遮住的词。这让 GLM 在预训练阶段就学会了生成——不需要像 BERT 那样在微调时添加额外的解码器。

### 2.4 Architecture Implication

GLM 的架构是一个 **Encoder-Decoder 混合体**：

- Part A（上下文部分）相当于 Encoder：双向注意力，把所有可见 token 编码为上下文表征
- Part B（空白部分）相当于 Decoder：因果注意力，在 Part A 的表征之上自回归生成

但和传统 Encoder-Decoder（T5）不同的是：
- T5 的 Encoder 和 Decoder 是**分开的两组参数**
- GLM 的"Encoder"和"Decoder"是**同一组参数**——只是注意力掩码不同

这使得 GLM 在参数效率上优于 T5，但架构复杂度仍高于纯 Decoder 模型。

## 第四章 多任务预训练

GLM 的训练不是单一目标——它包含了多个层面的任务统一。

### 4.1 三种预训练任务

```
任务类型 1: 短空白填充（核心）
  文本: "Transformer [MASK] attention mechanism."
  掩盖: 一个或多个连续的词
  长度: 通常掩盖 1-3 个词
  目的: 基础语言理解 + 生成

任务类型 2: 长空白填充
  文本: "Attention is all you need. [MASK 代表一段较长的文本] ..."
  掩盖: 一整个句子或段落
  长度: 几十到几百个词
  目的: 长程依赖建模 + 文档级理解

任务类型 3: 文档级理解
  文本: "整篇文章..." → 掩盖文档中的关键段落
  掩盖: 跨段落的多个空白
  目的: 全局理解 + 结构化生成
```

### 4.2 多任务指令预训练（MIP）

GLM 的一个关键创新是 **Multi-Task Instruction Pretraining（MIP）**——在预训练阶段就加入指令-响应数据，而不是在预训练之后的微调阶段才做：

```
传统模式:
  预训练（纯文本） → 微调（指令数据）
  ↑                        ↑
  学语言能力             学指令跟随
  两者有 gap

GLM 的 MIP 模式:
  预训练（文本 + 指令数据混合）
  ↑
  同时学语言能力和指令跟随
  gap 被消除
```

**MIP 的好处**：
- 模型在预训练阶段就见到了"指令-回答"的格式
- 减少后续对齐训练的负担
- 更自然的指令跟随能力

### 4.3 数据混合策略

GLM 的训练数据是多样化的混合：

```
训练数据构成:
  ├── 中文语料（网页、书籍、新闻、百科）：约 60%
  ├── 英文语料（Common Crawl、Books、维基百科）：约 30%
  ├── 代码（GitHub、技术文档）：约 8%
  └── 指令数据（人工标注 + 合成数据）：约 2%
       └── 这部分在 MIP 中在预训练阶段就加入了
```

## 第五章 关键架构细节

### 5.1 二维位置编码

GLM 使用 **2D 位置编码**，这是它区别于其他模型的关键技术细节：

```
问题：GLM 的输入包含两部分
  Part A：破坏后的文本（保留原文位置）
  Part B：被遮住的空白（没有原文位置）

解决方案：每个 token 有两个位置信息

对于 Part A 中的 token:
  位置 1: 原始文本中的位置（如 "我" 在第 1 位）
  位置 2: 0（表示在上下文部分）

对于 Part B 中的 token:
  位置 1: 它在原始文本中的位置
  （如空白是原文的第 3-4 个 token，则位置 3 和 4）
  位置 2: 它在生成序列中的位置
  （第 1 个生成的词位置 1，第 2 个位置 2...）

             原始位置维度
            ┌─────────────────┐
生成位置维度 │  Part A（双向）  │  Part B（因果）
   (0/1/2)   │  位置编码：原始pos │  位置编码：原始pos + 生成pos
            └─────────────────┘
```

**设计意图**：
- 原始位置维度：让模型知道被遮住的词在原文本中排在什么位置
- 生成位置维度：让模型知道当前生成的是第几个被遮住的词

编码方式通常以加法组合：
```
final_pos_encoding = PE(original_pos) + PE(generation_pos)
```

### 5.2 注意力机制

GLM 的注意力采用了混合设计：

```
注意力类型:

1. 双向自注意力（Part A 内部）
   每个位置看到 Part A 的所有位置
   不应用因果掩码
   类似 BERT 的注意力

2. 因果自注意力（Part B 内部 + Part B 看 Part A）
   Part B 的位置只能看到 Part A（全部）+ 更早的 Part B 位置
   应用因果掩码
   类似 GPT 的注意力

3. 跨位置混合
   掩码设计在单个 Transformer 层中实现
   不需要独立的 Encoder 和 Decoder 参数
```

**后期优化**：从 ChatGLM2 开始，引入了 **Flash Attention 2** 支持。在 GLM-4/5 中，使用了滑窗注意力 + 全局注意力的混合机制来处理超长上下文（128K → 1M+）。

```
滑窗注意力（Sliding Window Attention）:
  每个 token 只关注相邻的 W 个 token
  复杂度从 O(n²) 降为 O(n·W)

全局注意力（Global Attention）:
  特殊 token（如 [CLS]）关注所有位置
  保留全局信息

混合策略:
  大多数层：滑窗注意力（效率）
  少数层：全局注意力（信息完整性）
```

### 5.3 训练效率优化

从 ChatGLM2 开始的持续优化：

```
训练优化演进:

ChatGLM → GLM-4 → GLM-5:

├── Flash Attention 1/2/3 ✓
├── FP16 混合精度训练 ✓
├── INT8 / INT4 量化推理 ✓
├── 国产芯片适配:
│   ├── 昇腾 CANN 算子优化
│   ├── 摩尔线程 MUSA 适配
│   └── 寒武纪 MLU 适配
├── 分布式训练:
│   ├── ZeRO 阶段 2/3
│   ├── 张量并行（Tensor Parallelism）
│   └── 流水线并行（Pipeline Parallelism）
└── 长上下文优化:
    ├── Ring Attention（处理 1M+ 上下文）
    ├── 高效的注意力稀疏化
    └── 上下文缓存管理
```

## 第六章 比较：GLM vs GPT vs LLaMA

### 6.1 架构对比总表

| 维度 | GLM（Encoder-Decoder 混合） | GPT / LLaMA（Decoder-only） |
|------|----------------------------|-----------------------------|
| 训练目标 | **自回归空白填充** | 下一个词预测 |
| 架构类型 | 混合 —— 同一组参数，不同掩码 | 单一 —— 因果 Transformer |
| 理解类任务 | ✅ **天然优势**（双向编码） | ⚠️ 可做但不够自然 |
| 生成类任务 | ✅ 好（自回归空白） | ✅ **天然优势** |
| 长上下文 | ✅ 1M+（GLM-5） | ✅ 1M+（LLaMA-4、DeepSeek） |
| 架构复杂度 | **更高**（二维位置编码、双模注意力） | **更低**（简单、统一） |
| 参数效率 | ✅ 混合架构无额外参数 | ✅ 统一架构 |
| 训练稳定性 | ⚠️ 需要更精细的掩码调度 | ✅ 已验证 |
| 部署成本 | ✅ 单模型即可 | ✅ 广泛优化 |

### 6.2 为什么 Decoder-only 最终胜出

尽管 GLM 的混合设计在理论上更优雅，但 2023 年之后的行业事实是：

```
Decoder-only 胜出的原因:

1. 复杂度越简单，规模化越好
   Decoder-only 没有两种注意力模式的切换
   训练 pipeline 更简单
   分布式策略更直接

2. 足够的参数量弥补了"因果"缺陷
   当模型从 6B → 70B → 405B，因果注意力"看不到下文"的问题
   被更丰富的参数表达补偿了。足够大的 Decoder-only 模型
   在理解任务上并不差。

3. 生态效应
   整个开源社区（HuggingFace、vLLM、TensorRT-LLM）都是
   围绕 Decoder-only 优化的。GLM 的混合架构需要额外的
   工程适配。

4. 统一输入格式
   Decoder-only 可以统一处理所有任务：
   "Prompt → Response"
   不需要区分"编码阶段"和"生成阶段"
```

**但这不意味着 GLM 的路线是错误的**——它证明了混合架构的可行性，并且在实际应用中（尤其是需要双向理解的场景）仍有一定的架构优势。

### 6.3 与 T5 的比较

GLM 经常被拿来和 T5 比较，两者都是填空式预训练：

```
T5 vs GLM:

T5:
├── 完整的 Encoder + Decoder（两套参数）
├── 训练目标：Span Corruption（连续的 token 被替换为哨兵 token）
├── Encoder 双向，Decoder 因果
├── 使用哨兵 token（<extra_id_0>）标记空白位置
└── 参数利用率：较低（Encoder + Decoder 两套）

GLM:
├── 单组参数，两种掩码模式
├── 训练目标：自回归空白填充
├── Part A 双向，Part B 因果
├── 使用 [MASK] 标记，二维位置编码确定原始位置
└── 参数利用率：较高（同一组参数处理两种模式）

共同点:
├── 都采用"破坏文本 → 恢复"的范式
├── 都试图统一理解和生成
└── 都在中文领域有较好的表现
```

## 第七章 推理流程演练

以填空任务为例：输入 "我今天[MASK]车去[MASK]上班。" → 期望输出 "开着" 和 "公司"。

### Stage 1: 输入构造

```
原始文本: "我今天开着车去公司上班。"

第一步：随机选择要遮盖的连续片段
  片段 1: "开着"（位置 3-4）
  片段 2: "公司"（位置 7-8）

第二步：构建 Part A 和 Part B
  Part A: "我今天 [MASK] [MASK] 车去 [MASK] [MASK] 上班。"
  （注意：被遮住的位置保留 [MASK] token 标记位置数量）

  Part B: "开着公司" → 被随机打乱为 "公司开着"（顺序不影响）

  实际按遮盖的原始顺序: ["开着", "公司"]
  所以 Part B 按照这个顺序排列

第三步：拼接
  输入 = [Part A token ids] + [Part B token ids]
  二维位置编码: Part A 的 token 使用原始位置；Part B 使用原始位置 + 生成位置
```

### Stage 2: 前向传播

```
Part A 阶段（双向注意力）:
  "我今天[MASK][MASK]车去[MASK][MASK]上班。"
  所有 token 互相可见
  编码为上下文表征

Part B 阶段（因果注意力）:
  生成位置 1: "开着"
    → 能看到 Part A 的全部 + 暂无其他 Part B token
    → 预测输出: "开"

  生成位置 2: "着"
    → 能看到 Part A 的全部 + "开"
    → 预测输出: "着"

  生成位置 3: "公司"
    → 能看到 Part A 的全部 + "开着"
    → 预测输出: "公"

  生成位置 4: "司"
    → 能看到 Part A 的全部 + "开着公司"
    → 预测输出: "司"
```

### Stage 3: 损失计算

```
损失只在 Part B 区域计算:

位置 1 (预测"开"): 交叉熵(预测分布, "开"的 one-hot)
位置 2 (预测"着"): 交叉熵(预测分布, "着"的 one-hot)
位置 3 (预测"公"): 交叉熵(预测分布, "公"的 one-hot)
位置 4 (预测"司"): 交叉熵(预测分布, "司"的 one-hot)

总损失 = 各位置损失之和 / Part B 长度
```

### Stage 4: 推理时的自回归生成

推理时，GLM 的自回归生成和 GPT 类似——没有 Part A/Part B 的区分，完全作为因果语言模型工作：

```
推理流程:
  用户输入: "介绍一下北京的景点。"
            ↓
  GLM 按标准因果方式生成回复
  （因为不需要填空，模型的注意力退化为纯因果模式）
            ↓
  输出: "北京有很多著名的景点，比如故宫、长城、颐和园..."
```

这种"预训练用填空、推理用生成"的模式，和 T5 的"Encoder 编码 + Decoder 生成"不同：GLM 在推理时退化为纯 Decoder，而 T5 在推理时仍然需要两个模块。

### 8.4 Agent-first 方向

GLM-5 系列的核心定位是 **Agent 优先**——模型不是为"单轮问答"设计的，而是为"复杂任务闭环"设计的：

```
Agent 能力层次:

L1 - 工具调用（GLM-4）
    模型能调用 API、执行函数

L2 - 多步规划（GLM-5）
    模型能分解复杂任务，规划执行步骤

L3 - 自主执行 + 修正（GLM-5.2）
    模型能执行多步任务，在遇到错误时自动修正
    能调用多个工具的组合来完成系统工程任务

应用场景:
├── 代码工程：自主开发整个功能模块
├── 数据分析：端到端的数据处理 + 分析 + 报告
├── 自动化运维：监控、诊断、修复的系统闭环
└── 复杂研究：文献搜索 + 实验设计 + 结果分析
```

## 第九章 一句话总结

```
GLM 的核心 insight:
    "不要选边站。用自回归填空让一个模型同时学好理解和生成。"

GLM 的架构选择:
    Encoder-Decoder 混合 → 同一组参数、两种注意力模式
    ↓
    预训练用填空（双向+因果），推理用生成（因果）
    ↓
    理论上最优，实践中复杂度高于 Decoder-only

GLM 的行业地位:
    中国最早、最持续的开源大模型
    自回归空白填充（Autoregressive Blank Infilling）的全球先驱
    开源智能指数 #1（GLM-5.2, 2026）
    首家上市的纯 LLM 公司
    国产芯片适配最彻底的模型

GLM 的历史教训:
    混合架构在理论上更优雅——能同时做到双向理解和单向生成
    但 Decoder-only 用"足够大的规模"证明了：简单就是竞争力
    这不是 GLM 的错——而是 scaling law 的事实
```

## 第十章 影响

### 10.1 对中国开源生态的贡献

GLM 系列是中国 AI 开源生态中坚持最久的模型系列之一。从 2021 年的 GLM-10B 到 2026 年的 GLM-5.2，它覆盖了中国大模型创业从无到有的完整周期。中国开源社区中，GLM 是开发者最熟悉的本土模型之一。

### 10.2 架构探索的遗产

GLM 的 Encoder-Decoder 混合架构虽然没有成为行业主流，但它在架构探索历史上的地位是明确的：
- 证明了混合注意力可以在单组参数中实现
- 展示了二维位置编码的有效性
- 验证了"自回归空白填充"作为通用预训练目标的可行性

### 10.3 从智谱看中国 LLM 的独特道路

智谱AI 的发展路径展示了中国 LLM 公司的独特选择：
- 不是简单追随 OpenAI 的路线
- 坚持开源对抗闭源生态
- 国产芯片适配作为战略护城河
- Agent-first 作为差异化竞争方向

2026 年智谱AI 的上市，让这条道路的商业可行性得到了资本市场的验证。
