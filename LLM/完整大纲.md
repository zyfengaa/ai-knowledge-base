# LLM 知识体系完整大纲

> 领域：大语言模型（Large Language Model）
> 一句话描述：基于 Transformer 架构的大规模语言模型——从注意力机制的数学原理到 Agent 系统的工程实践
> 时间跨度：2017（Transformer）→ 2025（前沿）

## 二、模块划分（6 个正交维度）

| 模块 | 核心问题 | 设计思想 |
|------|---------|---------|
| **01 — Transformer 起源** | Attention 机制为什么能取代 RNN？ | 用「全连接的位置相关性」替代「隐状态的序列传递」——完全并行化 |
| **02 — 架构演进迭代** | 从原始 Transformer 到 LLaMA 架构，6 年做了哪些关键改进？ | 每个组件从「能用」到「好用」的精细迭代：位置编码→注意力→归一化→激活函数 |
| **03 — 训练与对齐范式** | 怎么让 LLM 从「背语料」到「听人话」？ | 预训练学知识 → SFT 学格式 → RLHF/DPO 学偏好，三层递进 |

| **05 — 应用技术** | 怎么让 LLM 在真实任务中可靠工作？ | 外部知识注入（RAG）+ 推理能力激发（CoT）+ 基础 Prompt Engineering |

## 三、范式跃迁：7 次「解决问题 → 留下麻烦」

### 范式 1：Seq2Seq + Attention 时代（~2017）

| 解决的问题 | 留下的麻烦 |
|-----------|-----------|
| RNN 能处理变长序列，Attention 缓解了长距离遗忘问题 | 序列依赖使训练无法并行；长程依赖仍会衰减；时间步线性不可绕过 |

### 范式 2：Transformer 革命（2017）

| 解决的问题 | 留下的麻烦 |
|-----------|-----------|
| Self-Attention 实现完全并行化，所有位置直接交互；O(1) 路径长度彻底解决长程遗忘 | Self-Attention 的 O(n²) 复杂度成为新瓶颈；模型没有位置感，必须加位置编码；深层训练不稳定 |

### 范式 3：预训练 + 微调范式（2018-2020）

| 解决的问题 | 留下的麻烦 |
|-----------|-----------|
| GPT / BERT 证明无监督预训练 + 有监督微调的有效性；一个预训练模型适配多种下游任务 | 每项任务都要微调，成本高；Encoder-only 和 Decoder-only 路线分歧；涌现能力是意外发现，不可控 |

### 范式 4：Scaling Law 时代（2020-2022）

| 解决的问题 | 留下的麻烦 |
|-----------|-----------|
| GPT-3 证明「模型够大 → 能力涌现」；In-Context Learning 使推理时无需微调 | 训练成本爆炸（GPT-3 ≈ .6M）；模型越大越难对齐；幻觉、有害输出等安全问题凸显 |

### 范式 5：对齐革命（2022-2023）

| 解决的问题 | 留下的麻烦 |
|-----------|-----------|
| InstructGPT 用 RLHF 让模型遵循人类指令；ChatGPT 验证产品化可行性 | RLHF 流程复杂（4 个模型 + PPO 不稳定）；DPO 虽简化仍需大量偏好数据；开源社区追赶需低成本对齐方案 |

### 范式 6：开源生态 + 架构定型（2023-2024）

| 解决的问题 | 留下的麻烦 |
|-----------|-----------|
| LLaMA 证明「小模型 + 更多数据 + 更久训练」也能强；RoPE + GQA + SwiGLU + RMSNorm 组合成为事实标准 | LLaMA 系列架构趋同，差异化空间变小；推理成本仍是产品化的核心壁垒；长上下文（128K+）仍受限于注意力复杂度 |

### 范式 7：MoE + Agent + MLLM（2024-2025）

| 解决的问题 | 留下的麻烦 |
|-----------|-----------|
| MoE 用稀疏激活突破参数限制（Mixtral 8×7B 仅激活 12.9B）；ReAct Agent 打开 LLM + 工具调用的新维度 | MoE 的路由不均衡 / 额外通信开销；Agent 可靠性无保证（错误积累）；评估体系远落后于实践；多模态融合深度不够 |

## 四、四大模块拆解层

### 第 1 层：信号 / 输入层 — 文本怎么变成向量

`
文本 → Tokenization（BPE / SentencePiece / TikToken）
     → Token Embedding
     → Position Encoding（Absolute / RoPE / ALiBi / YaRN）
     → 模型输入张量 [batch, seq_len, d_model]
`

- **核心权衡**：Token 粒度（词级 vs 子词 vs 字符）→ 越细粒度越灵活但序列越长
- **关键工作**：RoPE (2021)，TikToken (2024)，SentencePiece (2018)
- **当前状态**：RoPE 是事实标准，YaRN 和 NTK-aware 用于长度外推

### 第 2 层：核心范式层 — 三种架构路线的选择

| 范式 | 核心优点 | 核心代价 | 关键约束 | 代表模型 |
|------|---------|---------|---------|---------|
| **Encoder-only** | 双向上下文，理解能力最强 | 不能做生成任务 | ❌ 非自回归 | BERT, RoBERTa |
| **Decoder-only** | 统一预训练 + 生成，Scaling 最顺畅 | 单向注意力损失一些理解精度 | ✅ **当前事实标准** | GPT 系列, LLaMA, Qwen, DeepSeek |
| **Encoder-Decoder** | 编码器双向 + 解码器自回归，灵活度最高 | 参数翻倍，复杂度高 | ❌ 工业界少用 | T5, BART |

**贯穿轴：理解深度 ↔ 生成能力的权衡。Decoder-only 胜出的原因：Scaling Law 下架构越简单越容易扩展。**

### 第 3 层：模型架构层 — 从原始 Transformer 到现代标准配置

| 组件 | 原始 Transformer (2017) | 关键改进 | 现代标准 (2023-) | 解决的问题 |
|------|------------------------|---------|-----------------|-----------|
| 位置编码 | Sinusoidal | → RoPE (2021) | RoPE | 可外推到更长序列 |
| 注意力计算 | MHA（标准实现） | → FlashAttention (2022) | FlashAttention | IO 瓶颈，训练速度提升 2-4x |
| 注意力头设计 | MHA（全部头独立） | → GQA (2023) / MLA | GQA | 推理时 KV Cache 减半 |
| 归一化 | Post-LayerNorm | → Pre-RMSNorm (2019) | RMSNorm | 训练更稳定，去掉了 mean centering |
| 激活函数 | ReLU | → SwiGLU (2020) | SwiGLU | 训练损失更低，收敛更快 |
| 残差连接 | Post-Norm (Add → Norm) | → Pre-Norm (Norm → Add) | Pre-Norm | 深层训练不爆炸 |

**当前事实标准：RoPE + GQA + SwiGLU + RMSNorm + FlashAttention（LLaMA 3 / Qwen 2.5 / DeepSeek V2 共享这套配置）**

### 第 4 层：数据范式层 — 不同数据量级下的最佳策略

`
你有多少标注数据？
├── < 100 → Prompt Engineering（Zero-shot / Few-shot）
│   ╰ 不需要训练，靠 ICL 和 CoT 激发能力
│
├── 100 ~ 1,000 → LoRA / Adapter 微调
│   ╰ 冻结大部分参数，只训低秩适配器
│
├── 1,000 ~ 10,000 → SFT + DPO
│   ╰ 先微调指令格式，再用偏好优化对齐
│
└── > 10,000 → 全参数微调 / 继续预训练
    ╰ 数据质量比数量更重要（LIMA 原则：1,000 高质量样本就够了）
`

**一个贯穿问题**：数据质量 vs 数据数量——「Scaling Law 说越多越好，但 LIMA (2023) 说 1,000 条高质量数据就够了」→ 答案：预训练阶段数量优先，对齐阶段质量优先。

## 七、当前前沿开放问题（2024-2025）

### 1. 推理效率瓶颈
- 长上下文推理仍是 O(n²)，KV Cache 随序列长度线性增长
- FlashAttention 缓解了训练问题，但推理场景的 Cache 管理（PagedAttention / Ring Attention）仍在发展中
- **为什么难**：Attention 的「每个位置看所有位置」是架构级别的选择，底层限制了复杂度

### 2. 评估体系滞后于实践
- MMLU / GSM8K / HumanEval 等主流 Benchmark 趋于饱和
- Agent 场景的评估（工具调用准确性 / 多步推理一致性）尚未形成共识标准
- **为什么难**：开放式任务天生难做自动评估，人工评估成本高且不标准化

### 3. 对齐的成本困境
- RLHF 流程需要 4 个模型（Base + SFT + Reward + Policy），训练不稳定
- DPO 简化了流程但偏好的「边界」在哪里仍不清楚——模型学会「不说错话」但没学会「什么该说」
- **为什么难**：对齐本质是价值判断，没有数学上的最优解

### 4. 幻觉根源未解
- RAG 和检索增强缓解了事实性幻觉，但模型仍会「自信地编造」——这是自回归生成「自洽优先于事实」的固有倾向
- **为什么难**：语言模型的训练目标（next token prediction）和「说真话」不是同一个目标

### 5. Agent 可靠性
- ReAct / Function Calling / MCP 打开了 LLM + 工具的组合，但单步错误会积累、工具调用失败无优雅恢复
- **为什么难**：Agent 是一个开环系统，而 LLM 的能力边界目前只能靠「概率」表达，没有「确定性保证」

### 6. 长上下文「能用但不完美」
- 100K+ token 上下文窗口已成为标配（GPT-4 128K / Gemini 1M），但「中间丢失」效应表明模型在中段的注意力稀疏
- **为什么难**：这是 Soft Attention 的固有属性——长序列中 Attention 分数被稀释
