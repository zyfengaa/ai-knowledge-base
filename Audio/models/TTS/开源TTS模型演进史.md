# 开源 TTS 模型演进史（2016-2026）

> 只收录有可下载权重/代码的**真正开源**或业界影响力极大的模型。每个模型的前置条件是理解它"为什么出现在这个时间点"的关键。

---

## 2016 — WaveNet · DeepMind

### 前置条件：传统语音合成没有"生成"概念

2016 年之前的语音合成是两条老路：

- **拼接合成**：录制上万句语料库，运行时检索最佳音素片段拼接。存储极大（GB 级），拼接边界有可闻断裂，换一个说话人就要重录整个语料库
- **统计参数合成（HMM）**：用隐马尔可夫模型建模声学参数（基频、频谱包络、非周期成分），再用参数合成器（如 STRAIGHT）还原波形。不用大语料库，但音质明显有"机器味"，清音/浊音过渡处尤其不自然

两者都需要大量语言学特征手工设计——音素时长、基频轮廓、停顿时长——而且换语种几乎要重做整个前端规则。**没有人想到"直接用深度神经网络从零生成原始波形"**。

### WaveNet

- **架构**：因果膨胀卷积（Dilated Causal Convolution）
  - 堆叠膨胀率 1, 2, 4, 8, … , 512 的卷积层，每层输出门控激活 `z = tanh(W_f * x) ⊙ σ(W_g * x)`
  - 因果保证输出只依赖当前和过去的采样点，符合自回归时序——但代价是感受野受限，必须用膨胀把层数压下来
- **量化**：16-bit 波形（65536 个可能值）→ μ-law 256 路离散分类。把回归问题转化成分类问题，大幅降低学习难度
- **生成方式**：自回归逐点预测——生成第 t 个采样点时，需要前面所有采样点作为条件。**1 秒音频（16kHz = 16000 点）生成需要数十分钟**
- **训练数据**：英语多说话人多语种语音数据库（具体来源未公开），数万小时级别
- **效果**：MOS > 4.0，首次深度生成模型音质显著超越传统参数合成。**WSJ 数据集上 MOS 4.21，同期 HMM 合成 3.67，拼接合成 3.86**
- **局限**：逐点自回归生成速度完全不可用于产品；没有文本条件控制能力（只是"生成语音"而非"说出某句话"）
- **开源**：❌ DeepMind 未发布官方权重和完整训练代码。Google 在 TensorFlow 中开源了推理实现，但预训练权重从未公开

### 遗留遗产

WaveNet 确立了"用深度生成模型直接合成波形"的方向，但它自己因为逐点自回归的速度瓶颈没有直接成为产品。此后所有 TTS 声码器（WaveGlow、MelGAN、HiFi-GAN、LPCNet）的共同目标都是：**保留 WaveNet 的音质、跑出实时的速度。**

## 2017 — Tacotron 1 · Google

### 前置条件：TTS 管线太长，组件各自为政

2017 年的 TTS 生产管线包含四个独立组件：

1. **文本前端**：分词、注音（G2P）、韵律边界预测——每种语言要单独写规则，工作量巨大
2. **时长模型**：预测每个音素持续多少帧
3. **声学模型**：从语言学特征预测声学参数（梅尔谱/线性谱/基频）
4. **声码器**：从声学参数还原波形

每个组件由不同的人、用不同的算法、不同的训练框架来维护。线上出了问题——到底是前端韵律边界标错了、时长模型预测偏了、还是声码器参数不对？**排查需要横跨四个团队。** 整个行业在等一个模型把这一切统一起来。

### Tacotron 1

- **架构**：Encoder-Attention-Decoder + CBHG 后处理网络
  - Encoder：字符嵌入（one-hot 256 维嵌入）→ Pre-Net → CBHG 提取上下文表征
  - Decoder：RNN + Attention（内容加性注意力）逐帧生成频谱
  - Post-Net：CBHG 模块对频谱做精细化
- **关键创新**：**首次端到端 TTS**。输入纯文本字符，输出线性频谱图，不需要音素标注、不需要时长模型、不需要语言学特征工程
- **CBHG 模块**：1 路 Conv Bank（filter size 1~16）并行提取多尺度特征 → 拼接 → MaxPool → Highway Net → BiGRU。功能上类似后来的多路卷积 + 双向 RNN——用多个不同尺度的卷积核捕捉语言的不同粒度特征（单字母到多字母组合）
- **波形重建**：Griffin-Lim 算法——一种迭代相位重建方法，不需要训练，但音质上限低（相位估计不准导致"嘶嘶"噪声）
- **训练数据**：LJSpeech-1.0（24 小时单说话人英语有声书），NVIDIA 内部数据
- **效果**：MOS 3.82，接近当时拼接合成水平（3.86）。**第一次让人看到"给模型纯文本，模型直接说出话来"**
- **局限**：
  - Griffin-Lim 相位重建是瓶颈——频谱预测再好，还原成波形时音质就掉了
  - Attention 在长文本（>100 字符）下易出现字重复或跳词
  - 英文表现明显好于其他语言（G2P 知识完全靠模型自己学，没给音素提示）
  - 训练慢（自回归逐帧生成频谱）
- **开源**：❌ Google 未发布官方权重。TensorFlow 实现代码在 Google 的 GitHub 仓库中公开（非官方 repo），社区有大量 PyTorch 复现

## 2018 — Tacotron 2 · Google

### 前置条件：端到端路线可行，但声码器是瓶颈

Tacotron 1 证明了端到端可行，但限制很明确：
1. Griffin-Lim 音质上限低——凭什么频谱预测再好也要被这个无训练的相位算法拖后腿？
2. WaveNet 音质好但只能做声码器——能不能把 Tacotron 1 的频谱预测和 WaveNet 的波形生成组合起来？

**Tacotron 2 就是"Tacotron 1 的频谱预测网络 + WaveNet 声码器"的组合。**

### Tacotron 2

- **架构**：
  ```
  字符嵌入 → 3 层 Conv (512 filters, 5x1) → BiLSTM Encoder (512 units)
    → Location-Sensitive Attention (128 units)
    → 2 层 Pre-Net (256 ReLU) → 2 层 LSTM Decoder (1024 units)
    → 5 层 Conv Post-Net (512 filters, 5x1，残差连接)
    → 线性投影 → Mel 频谱 (80 bands)
    → WaveNet 声码器 → 波形
  ```
- **改进点**：

  | 维度 | Tacotron 1 | Tacotron 2 | 原因 |
  |------|-----------|-----------|------|
  | 输出目标 | 线性频谱图（含相位） | **Mel 频谱**（丢弃相位） | Phase 交给声码器，Mel 更符合人耳感知——模型专注做频谱幅度预测 |
  | Attention | 标准加性 Attention | **Location-Sensitive Attention** | 往 Attention 中加历史对齐的卷积特征——上一帧对齐到哪里，下一帧大概率还在附近，减少跳词 |
  | Post-Net | CBHG | **5 层 Conv 残差** | 轻量残差网络直接修正频谱残差——比 CBHG 更高效 |
  | 声码器 | Griffin-Lim（无训练） | **条件 WaveNet** | WaveNet 以 Mel 为条件生成波形——音质从"能听"到"接近真人" |
  | 停止预测 | 固定帧数 | **Stop Token（线性投影 + Sigmoid）** | 模型自己判断语音是否结束——不再需要预设输出帧数 |

- **训练数据**：LJSpeech + 更多内部数据，总计约 50 小时
- **效果**：MOS **4.53**（人类录音 4.58）。**首次深度学习 TTS 接近人类水平。** 被 Google 用于 Google Assistant（2019 年起部分流量切换至 LSTM + WaveNet）
- **局限**：
  - 自回归逐帧生成——GPU 生成 1 秒音频约需 0.5-1 秒实时
  - Location-Sensitive Attention 在极长文本（>200 字符）下偶有对齐漂移
  - 两阶段误差累积——声学模型的 Mel 预测误差会传递给声码器放大
  - 换说话人需要重新训练或至少 fine-tune
- **开源**：❌ Google 未发布官方权重。NVIDIA 提供官方 PyTorch 复现版（Tacotron 2 + WaveGlow），是社区使用最广的版本

### 历史地位

Tacotron 2 是深度学习 TTS 的"经典架构"。此后数年内，几乎所有 TTS 系统都沿用 Encoder-Attention-Decoder 框架，只是把 WaveNet 换成更快的声码器（WaveGlow、HiFi-GAN）。**Tacotron 2 + HiFi-GAN 组合是 2018-2022 年间部署最广的 TTS 方案。**

## 2020 — FastSpeech 2 · 微软

### 前置条件：自回归 TTS 太慢了

Tacotron 2 音质好但有两个结构性问题：

1. **逐帧自回归**：Decoder 生成第 t 帧必须等待第 t-1 帧完成后才能开始。**长句下 GPU 利用率低，延迟和句子长度成正比**
2. **Attention 不可控**：隐式 Attention 对齐在训练中可能出现"跳词"或"重复"，尤其跨语言场景——生产环境不能容忍这种非确定性行为

**如果能一次性并行生成所有 Mel 帧**，速度提升几十倍；用显式时长预测器替代 Attention，对齐就完全可控。

### FastSpeech 2

- **架构**：
  ```
  音素 → FFT Block Encoder (N=4) → Variance Adaptor → Length Regulator → FFT Block Decoder (N=4) → Mel 谱 → HiFi-GAN → 波形
  ```
- **关键创新——Variance Adaptor**：三个预测器替代 Tacotron 的隐式 Attention

  | 预测器 | 输入 | 输出 | 效果 |
  |--------|------|------|------|
  | Duration Predictor | 音素编码器输出 | 每个音素持续帧数 d_i | 显式控制语速，无 Attention 不稳定。**d_i 从 MFA（Montreal Forced Aligner）自动标注获得** |
  | Pitch Predictor | 每帧编码器输出 | 每帧基频值（连续/量化） | 控制语调起伏——英语问句末尾语调上扬，没有这个模块做不到 |
  | Energy Predictor | 每帧编码器输出 | 每帧能量值 | 控制重音和节奏——强调某词时能量增大 |

- **Length Regulator**：将音素隐藏状态按预测时长 d_i 重复展开——如果"a"音素持续 3 帧，就把它的隐藏状态复制 3 份。简单但有效

- **训练数据**：LJSpeech + LibriTTS（多说话人），全景约 600 小时
- **训练方式改进**：
  - FastSpeech 1：用预训练 Tacotron 2 做知识蒸馏提取时长——**依赖另一个模型**
  - FastSpeech 2：用 MFA（Montreal Forced Aligner）自动对齐——**独立训练，不再需要教师模型**
  - FastSpeech 2s：进一步加入波形解码器（WaveNet），实现文本→波形全并行端到端
- **速度**：比 Tacotron 2 **快 30–270 倍**（全并行，无自回归依赖）
- **效果**：MOS ~4.45，略低于 Tacotron 2（4.53），但极为接近。**速度换音质的代价很小。**
- **意义**：**非自回归 TTS 从此成为主流分支。** 此后的 Glow-TTS、VITS（Flow 部分）都受其"显式对齐+并行生成"思路影响。
- **局限性——"梅尔谱平滑"**：非自回归生成倾向于均值回归，频谱细节不如自回归丰富，听感上"略模糊"
- **开源**：✅ MIT License，GitHub `microsoft/fastspeech2`，HuggingFace 提供预训练权重

## 2021 — VITS · KAIST

### 前置条件：TTS 为什么还是两阶段？

截至 2021 年，所有实用的 TTS 都是两阶段——声学模型（文本→Mel）+ 声码器（Mel→波形）。两阶段的本质问题：**声学模型不知道声码器会怎么处理它的输出。** 声学模型训练用 L1 Mel loss，声码器推理用 Mel 做条件——两个目标不完全一致。能不能一个模型直接从文本生成波形？

### VITS

- **架构**：VAE（变分自编码器）+ Normalizing Flow（归一化流）+ GAN（生成对抗网络）+ MAS（单调对齐搜索）融合为一个端到端模型

  ```
  训练阶段：
  真实波形 → Posterior Encoder（非因果 WaveNet 残差块）→ 隐变量 z ~ N(μ,σ)
  文本 → Text Encoder（FFT Block + 音素嵌入）→ h_text → Normalizing Flow → 先验分布 N(μ,σ)
    → MAS（单调对齐搜索）找到音素与帧的最优对齐
    → Stochastic Duration Predictor（概率分布建模时长）
    → HiFi-GAN Decoder → 波形

  推理阶段：
  文本 → Text Encoder → Normalizing Flow → 从先验分布采样 z
    → Duration Predictor 预测时长 → 展开 → HiFi-GAN Decoder → 波形
  ```

- **MAS（Monotonic Alignment Search）**：用动态规划找到文本音素与语音帧之间的**最优单调对齐路径**。不是 Attention 那样的软对齐（soft alignment），而是硬对齐（hard alignment）——每个音素对应一个连续的帧区间。训练时以真实频谱为参照做最优搜索，**不需要外部对齐工具**
- **Stochastic Duration Predictor**：把时长建模为**概率分布**而非固定值。推理时加入随机采样——同一句话每次生成的节奏略有不同，更自然
- **损失函数——四个目标同时优化**：
  - L1 重建损失（Mel 一致性）
  - KL 散度（后验与先验分布对齐）
  - GAN 对抗损失（HiFi-GAN Decoder vs Multi-Period Discriminator）
  - 特征匹配损失（稳定 GAN 训练）
- **训练数据**：LJSpeech + VCTK（多说话人）+ 更多公开数据
- **效果**：MOS ~4.43，单阶段端到端。**不需要单独训练声码器，模型直接从文本生成波形**
- **局限**：
  - VAE+GAN 联合训练极不稳定，调参成本高。**模型对其他说话人/语言的泛化能力有限**
  - 零样本语音克隆能力弱——没有专门的说话人编码器
  - 推理速度中等（Flow + HiFi-GAN 的计算量大）
- **开源**：✅ MIT License，GitHub `jaywalnut310/vits`

### 社区生态——VITS 的真正影响力

VITS 开源后衍生出数十个项目，是**社区生态最活跃的 TTS 模型**：

| 衍生项目 | 方向 | 热度 |
|---------|------|------|
| Bert-VITS2 | 用 BERT 替换文本编码器，语义理解更强 | 中文社区广泛使用 |
| GPT-SoVITS | GPT + VITS，少样本语音克隆 | ⭐ 最火衍生项目，B 站大量教程 |
| SoVITS-SVC | 唱歌声音转换 | 翻唱/虚拟歌手社区流行 |
| MoeGoe | VITS 轻量推理引擎（ONNX/C++） | 端侧部署 |

VITS 代表了"生成模型融合进 TTS"的最高潮——此后 TTS 走向 Flow Matching 和扩散模型，不再走 VAE+GAN 路线。

## 2023 — Bark · Suno

### 前置条件：TTS 能不能不做"文本→语音"映射？

传统 TTS 隐含假设：输入文本 → 音素/时长/对齐 → 声学特征 → 波形。每一步都是手工设计的管线。

但 2023 年 GPT 系列（尤其是 GPT-3/ChatGPT）的成功让人思考另一个方向——**能不能把语音当成另一种语言，用纯语言模型的方式生成？** 这样：
- 不需要强制对齐（alignment-free）
- 不需要音素/时长预测器
- 不需要声码器
- 甚至不需要"只能生成语音"——笑声、叹气、背景音都可以作为"词汇"加入

### Bark

- **架构**：3 个 GPT 风格 Transformer 串行工作
  ```
  文本 → [Semantic Transformer] → 语义 token 序列（~7.5Hz）
       → [Coarse Transformer] → 粗粒度声学 token
       → [Fine Transformer] → 细粒度声学 token
       → EnCodec 解码器 → 波形
  ```
- **为什么拆成三个 Transformer？** EnCodec 的 RVQ 输出有多层码本——第一层主要包含语义（说了什么），后面几层包含声学细节（语气、音色、环境）。三个 Transformer 分别对应语义 / 粗声学 / 细声学三个粒度

- **特殊能力——非语言声音**：文本中使用 `[laughs]`、`[sighs]`、`[music]`、`[clears throat]` 等标记，**模型直接生成对应的非语言声音**。这是唯一一个在开源层面支持这种能力的 TTS 模型
- **多语言**：13 种语言（中英日德法韩西等），自动语种检测，**同句话内可混用多种语言**
- **训练数据**：未公开详细来源（疑似 YouTube + 有声书）
- **效果**：自然度高、韵律丰富、非语言声音生成效果惊艳
- **局限**：
  - **幻觉严重**：短句末尾经常生成无意义的"umm"、"hmm"填充音
  - **原生音色克隆能力极弱**：生成的声音由随机种子决定
  - 推理极慢：**三个 Transformer 串行** + EnCodec 解码
  - CPU 推理约 30-60x 实时率
- **开源**：✅ MIT License，GitHub `suno-ai/bark`

### 历史定位

Bark 不是音质最好的 TTS，甚至不是最实用的。但它打开了"TTS 可以用纯语言模型做，而且能做传统 TTS 做不到的事情（非语言声音）"的思路。此后的 ChatTTS、Fish Speech、GPT-SoVITS 都在不同程度上继承了"语言模型生成语音 token"的范式。

## 2024 — ChatTTS

### 前置条件：现有 TTS 的"朗读感"太重

所有主流 TTS（Tacotron 2、FastSpeech 2、VITS 等）训练数据基本来自有声书朗读——**读得像播音员**而不是在聊天。真实对话中的停顿癖、重音偏移、语速快慢、语气词（嗯、啊、那个）的韵律变化——这些模型学不到，因为它们训练数据里没有。

同时，2024 年语音 AI 助手（Character.AI、星野、Glow）爆发式增长。用户和 AI 对话时需要的不是"朗读"，而是"聊天"。市场在等一个听起来像真人在聊天的 TTS。

### ChatTTS

- **架构**：DVAE（自监督语音编码器）+ LLM + SED（Smoothed Exponential Decay）解码器
  ```
  音频 → DVAE Encoder → 离散语音 token（自监督，不需要文本标注）
  文本 + 韵律控制标记 → LLM 预测语音 token → SED Decoder → 波形
  ```
- **DVAE 亮点**：在大量无标注语音上自监督训练，不需要文本-语音配对数据——**这样可以从互联网海量音频中学习语音韵律的多样性**
- **训练数据**：27,000+ 小时中英文语音（含大量真实对话数据——播客、访谈、电话录音等）
- **韵律控制的粒度**：可以在 token 级别指定停顿长度（50ms~500ms）、语速（0.5x~2.0x）、语调升降区间。**这是开源 TTS 中最精细的韵律控制**
- **推理门槛**：4GB VRAM 可运行（FP16），CPU 可跑但慢
- **效果**：
  - 中文对话场景 MOS 4.2+，同期 Tacotron 2 约 3.5 左右在同等场景
  - **2024 年中文 AI 社区讨论热度最高的 TTS——知乎/B站/即刻在 1 周内出现上千条帖子**
  - 生成的语音有明显"聊天感"：会换气、句尾语调会自然下沉、不同角色的语速会体现性格差异
- **局限**：
  - 对话风格用在**正式朗读场景（新闻/有声书）** 反而奇怪——换气频繁、语气词多
  - 英文自然度明显不如中文（训练数据中文占比大）
  - 版权风险：训练数据来源不透明（27,000 小时对话数据从哪来？）——这是开源社区最关心的争议点
  - 长文本（>30 秒）稳定性下降
- **开源**：✅ Apache 2.0（基础版）/ CC BY-NC 4.0（大模型版），GitHub `2noise/ChatTTS`

## 2024 — CosyVoice 1.0 · 阿里通义（FunAudioLLM）

### 前置条件：TTS 和 ASR 能不能共用一套框架？

阿里通义实验室在 2024 年 7 月同时发布 SenseVoice（ASR，Encoder-only + CTC，70ms 延迟）和 CosyVoice（TTS）。两者组成 **FunAudioLLM** 框架——一个统一的语音大模型平台。

核心想法：**ASR 是"语音→文本"，TTS 是"文本→语音"**。两者的编码器-解码器结构天然对称。共用一套基础设施（GPU 集群、数据管线、推理服务），训练/部署/维护可以共享。

### CosyVoice 1.0（2024.07）

- **架构**：**Flow Matching** + Transformer Decoder，非自回归连续空间生成
  - 文本编码器（音素级别）→ 音素隐表征 + 说话人嵌入（3 秒参考音频 → Spk Encoder）
  - **Flow Matching**：在连续空间中通过 ODE 正向积分生成语音潜表征
  - 相比扩散模型的优势：**步数少（几步 vs 扩散的几十步）、训练稳定（无方差调度问题）、采样质量高**
  - 解码器 → 波形
- **核心能力——3 秒零样本语音克隆**：
  - Spk Encoder 从 3 秒参考音频中提取说话人嵌入
  - 不需要任何额外微调，直接克隆音色
  - **说话人相似度 SIM 0.78+**（同期 XTTS 约 0.64）
- **方言覆盖——开源 TTS 之最**：9 种语言 + **18 种中文方言**（粤语、吴语、闽南语、四川话等）
- **SFT 微调**：官方提供标准微调流程，5-10 分钟数据即可学会新声音或新方言。微调后说话人相似度提升至 0.85+
- **与 SenseVoice 的联动**：SenseVoice 识别文本 → CosyVoice 生成回复语音——一条完整语音交互链路
- **开源**：✅ Apache 2.0，HuggingFace `FunAudioLLM/CosyVoice-300M`，ModelScope 同步发布

### 影响

CosyVoice 1.0 是**第一个将 Flow Matching 大规模应用于 TTS 的开源模型**。它的方言覆盖和零样本克隆能力在中文场景直接对标 GPT-4o 的 TTS 能力，某些方言场景甚至超越。**FunAudioLLM 双模型框架在中文语音社区影响广泛。**

## 2024 — CosyVoice 2.0 · 阿里通义

### 前置条件：CosyVoice 1.0 离线不够快

CosyVoice 1.0 虽然音质和克隆效果好，但：
1. **非流式**：必须等整句生成完毕才能播放。端到端延迟 >300ms
2. **Flow Matching 在非因果设定下运行**：当前帧依赖未来帧的信息，不能基于部分输入就输出

实时语音交互（语音助手、实时通话、AI 面试官）需要**边生成边播放**，首包延迟在 100ms 级别。这要求 Flow 是**因果的**——当前帧只依赖过去帧。

### CosyVoice 2.0（2024.12）

| 升级点 | CosyVoice 1.0 | CosyVoice 2.0 | 原因 |
|--------|--------------|--------------|------|
| 编码频率 | ~12.5Hz | **25Hz** | 更高帧率 → 更细粒度控制，流式播放更平滑 |
| Flow Matching | 非因果（双向 attention） | **因果 Flow Matching** | 当前帧只依赖过去帧 → 可流式生成 |
| 流式能力 | ❌ 必须等整句 | ✅ **边生成边流式播放** | 首包延迟 <150ms |
| 端到端延迟 | >300ms | **<150ms** | 达到实时对话基本要求 |
| 参数量 | ~300M | ~500M |

- **核心创新——因果 Flow Matching**：在 ODE 求解过程中，确保每一步只用到过去的时间步信息。数学上是通过修改 ODE 的积分路径实现：`dx_t = v(x_t, t) dt` 中的 `v` 不再依赖未来帧
- **音质 vs 1.0**：因果 Flow 理论上音质略低于非因果（因为没有"回头修正"的机会），但实际听感差异很小。**延迟降低 50%+ 换来了几乎无损的音质**
- **开源**：✅ Apache 2.0，HuggingFace `FunAudioLLM/CosyVoice2-SpeechModel`

## 2024 — F5-TTS · 上海交大 X-LANCE

### 前置条件：Flow Matching 好，但能不能再简单点？

CosyVoice 和 VoiceBox 都用 Flow Matching 做 TTS，但它们仍然依赖传统组件：
- 显式时长预测器（Duration Predictor）
- 音素级别对齐（MAS 或外部 aligner）
- 文本编码器

如果 Flow Matching 本身已经足够强大——**可以直接学习文本和语音之间的映射关系，为什么要这些中间组件？** F5-TTS 的目标就是用最少的组件实现 TTS。

### F5-TTS

- **架构**：Flow Matching + DiT（Diffusion Transformer）+ ConvNeXt V2 条件编码器
- **设计哲学——极简**：
  - ❌ 无 Duration Predictor
  - ❌ 无音素对齐
  - ❌ 无文本编码器（字符直接输入）
  - 输入：文本字符 + 参考音频（3-10 秒）→ DiT 直接预测 Flow ODE 的速度场 → 采样生成语音
- **Sway Sampling**：推理时的自适应步数策略——语音复杂区域（辅音、音素过渡）自动用更多采样步数，平稳区域（元音持续段）用更少步数。**用相同的步数预算，音质比均匀采样好**（约 0.1 MOS 提升）
- **参数**：~335M
- **RTF（实时率）**：0.15（1 秒音频约 150ms 推理时间，对比 CosyVoice 1.0 约 0.3）
- **训练数据**：100K 小时 Emilia 多语言数据集（与 MaskGCT 共享数据资源）
- **效果**：
  - 零样本克隆自然度接近 CosyVoice
  - **流程简单到可以在单卡 A100 上 5 天内完成训练**（对比同期模型需要数周乃至数据中心级算力）
- **局限**：
  - 无显式对齐 → 长文本下偶有字重复或漏读（~5% 的长句有轻微问题）
  - 控制性弱：无法直接调节语速、语调（因为没有独立的速度/音调预测器）
- **许可**：✅ **MIT License**——最宽松的许可，商业友好
- **开源**：✅ GitHub `SWivid/F5-TTS`，HuggingFace 有权重
- **学术**：**ICLR 2025 接收**

### 影响

F5-TTS 是社区最受欢迎的"极简 TTS 基线"。MIT 许可 + 全流程开源 + 单卡可训 = 人人可以做自己的 TTS。**在学术对比实验中，F5-TTS 已取代 Tacotron 2 成为新的默认基线。**

## 2024 — Fish Speech 1.5 · Fish Audio

### 前置条件：零样本 TTS 的量不够大

2024 年的零样本 TTS 模型（YourTTS、XTTS、CosyVoice）使用数万小时级别数据训练。但对"任意说话人"的语音克隆，一个简单观察成立：**数据量直接决定零样本泛化能力**。更多数据 = 更好覆盖各种声学空间（不同录音环境、口音、声道特性）。

如果能把训练数据推到**百万小时级别**，零样本泛化能力可能质变。

### Fish Speech 1.5（2024.12）

- **架构——Dual-AR（双自回归）**：
  ```
  文本 → [Slow AR] (语义 Token 生成)
                    ↓
  粗粒度语义 token 序列 → [Fast AR] (声学 Token 生成)
                               ↓
  细粒度声学 token → 解码器 → 波形
  ```
  - Slow AR（~1B）：关注"说什么"——文本语义 → 粗粒度语音 token（~20Hz 帧率）
  - Fast AR（~400M）：关注"怎么说"——语音细节（音色、语气、背景）→ 细粒度 token（~80Hz）
  - 拆分而非合并到一个大模型：**语义和声学的建模难度不同，分开训两个小模型比合并训一个大模型更容易优化**

- **训练数据**：百万小时级多语言语音（Fish Audio 积累的商业数据 + 公开数据集）
- **语言支持**：中英日德法韩西等 10+ 主流语言
- **社区热度**：**GitHub 30K+ Stars**，提供 WebUI + REST API + Python SDK，上手门槛极低
- **关键特性**：文本内联标签 `[whisper]`、`[laugh]`、`[fast]` 控制语气和速度——类似 Bark 但更轻量
- **开源**：✅ Apache 2.0，GitHub `fishaudio/fish-speech`

## 2026 — Qwen3-TTS · 阿里通义

### 前置条件：TTS 的"100ms 门槛"还没人迈过

2026 年实时语音对话应用（语音助手、实时翻译、AI 语音原生交互）提出一个硬性要求：**端到端首包延迟 ≤ 100ms**。

当时最好的开源流式 TTS（CosyVoice 2.0）首包延迟约 150ms。虽然接近，但 100ms 是学术界和工业界公认的"实时交互门槛"——低于 100ms 人类几乎感受不到延迟，高于则能感知到"对方在等我"。

### Qwen3-TTS（2026.01）

**阿里开源的全栈 TTS 模型家族**，Apache 2.0 License。

### 全系列规格

| 型号 | 参数量 | 功能 | 所需显存 |
|------|--------|------|---------|
| **Base** | 1.7B / 0.6B | 3 秒零样本音色克隆 | ~5-6GB / ~3.5-4GB |
| **CustomVoice** | 1.7B / 0.6B | 9 种预置音色 + 指令控制 | ~5-6GB / ~3.5-4GB |
| **VoiceDesign** | 1.7B | **自然语言描述创造新声音** | ~5-6GB |

### 架构创新——离散多码本 LM + Dual-Track 流式

**词表架构的转变**：传统方法用扩散/Flow 在连续空间生成，Qwen3-TTS 回到离散 token 路线——用 16 层 RVQ（残差矢量量化）将音频编码为离散 token 序列，然后用 LLM 预测 token。

```
传统路线：文本 → 扩散/Flow（连续空间）→ 解码 → 波形
Qwen3-TTS：文本 → 离散多码本 LM（token 预测）→ 轻量 CNN 解码 → 波形
```

**为什么用离散 LM 而不是扩散/Flow？**
1. **非自回归不一定是更优解**——扩散/Flow 虽然并行生成，但语义连贯性在极长文本下不如自回归 LM
2. **多码本结构**：第 1 层编码语义（说了什么），后续 15 层渐进编码声学细节（语气、音色、环境）。**语义层决定理解准确性，声学细节层决定听感——两层目标不同，合在一起训LM反而冗余**
3. **推理效率**：LM 在 SGLang/vLLM 等经过高度优化的引擎上运行，延迟远低于扩散/Flow 的自定义 ODE solver

**Dual-Track 混合流式生成**：
- 单模型同时支持流式模式（低延迟）和非流式模式（高质量）
- 集成多 Token 预测（MTP）模块——预测完当前 token 时，顺便预测后面 2-3 个 token
- **首包延迟 97ms**：输入第 1 个字后约 97ms 即可开始播放

**VoiceDesign——自然语言音色设计**（开源领域唯一）：
- 不需要任何参考音频，完全从文本描述创造新声音
- 示例："略带紧张的 17 岁男生，音域偏高"、"温柔的中年女性，略带沙哑"
- InstructTTS-Eval 得分 **84.1 / 81.8**，超越 MiniMax-Voice-Design（商业闭源）

### 性能指标

| 评测维度 | Qwen3-TTS | 对比（同期最佳） |
|----------|-----------|----------------|
| Tokenizer 重建 PESQ | **3.21** | Mimi: 2.88 |
| 说话人相似度 SIM | **0.95** | 近乎无损保留 |
| 音色克隆 WER（英） | **1.24%** | CosyVoice 3: 1.45% |
| 跨语种克隆（zh→ko WER） | **4.82%** | CosyVoice 3: 14.4% |
| 长文本 WER（10min 英） | **2.81%** | Fish Speech S2: 3.2% |
| 流式端到端延迟 | **97ms** | 行业标准 <100ms |

### 部署细节

- PyPI 可安装：`pip install qwen-tts`
- 1.7B 模型在 A10G（24GB）上可运行流式推理
- 0.6B 模型在 T4（16GB）上全速运行
- 支持 ONNX 导出和 TensorRT 加速
- **开源**：✅ Apache 2.0，HuggingFace `Qwen/Qwen3-TTS-12Hz-1.7B-Base` 等全系列权重

### 前置条件：Dual-AR 的更大版本

Fish Speech 1.5 验证了 Dual-AR 路线的有效性。S2 的核心想法简单粗暴：**把模型和数据都推到极限——看看 Dual-AR 的天花板在哪里。**

### Fish Speech S2（2026.03）

| 升级点 | Fish Speech 1.5 | Fish Speech S2 | 原因 |

  - S2（基础版）：研究许可，HuggingFace 可下载
  - S2-Pro（增强版）：需商业授权。主要差异在更长训练步数和更多说话人的高质量微调

## 2026 — CosyVoice 3.0（Fun-CosyVoice）· 阿里通义

### 前置条件：生成语音的自然度还有空间

CosyVoice 2.0 流式延迟 <150ms，音质好，但两个问题仍然存在：
1. **说话人相似度不够稳定**：零样本克隆时，有 ~10% 的生成句会出现音色偏移——听着还是同一个人，但"感觉不太像"
2. **韵律不够自然**：长句（>15 秒）的重音和节奏偶尔"不对"——该重读的地方没重读，不该停顿的地方停顿了

这两个问题本质上是同一个根因：**生成模型对真实人类语音的数据分布拟合还不够好。** Flow Matching 能生成清晰的频谱、能复刻音色，但在"什么时候该重音、什么时候该停顿"这种高维韵律特征上，单纯增大模型和数据效果递减。

参考 LLM 领域经验：预训练模型做 SFT（监督微调）可以学到基础分布，但要用 RLHF（强化学习从人类反馈）才能对齐到"人类觉得好"的高维偏好。

### CosyVoice 3.0（2026.06）

- **核心提升——RL 对齐（RLHF）**：
  - 训练流程：CosyVoice 2.0 基座 → 多维度奖励模型 → PPO 强化学习
  - 奖励模型的四个维度：
    1. **说话人相似度**（Speaker Similarity）：参考音频和生成音频的嵌入余弦相似度
    2. **可懂度**（WER）：ASR 模型对生成语音的识别正确率
    3. **自然度**（Naturalness）：MOS 预测器打分
    4. **情感准确度**（Emotion Accuracy）：对含有情感要求的文本，检测生成语音的情感是否匹配
  - 训练数据：约 10 万条成对偏好数据（人工标注"A 的声音比 B 更自然 / 更像说话人"）
- **语言/方言**：在 1.0 的 9+18 基础上进一步扩展，新增少量低资源语言
- **说话人相似度**：SIM > 0.92（对比 2.0 约 0.87）。**RL 对齐让"音色偏移"的发生率从 ~10% 降到 ~2%**
- **开源**：✅ Apache 2.0，HuggingFace `FunAudioLLM/Fun-CosyVoice`，ModelScope 同步

CosyVoice 系列是**中文 TTS 领域影响最大的开源项目系列**，1.0 到 3.0 覆盖了"能做 → 能流式 → 能做更好"的完整演进路径。
