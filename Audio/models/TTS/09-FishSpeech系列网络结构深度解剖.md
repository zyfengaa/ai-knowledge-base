> Fish Audio 出品 | Dual-AR（双自回归）路线 | SOTA 质量
> Fish Speech 1.5 (2024.12) → Fish Speech S2 (2026.03) | 30K+ GitHub Stars

---

## 写在前面：Dual-AR 路线

Fish Speech 是唯一坚持**纯自回归路线**的主流开源 TTS。当 CosyVoice 和 F5-TTS 走向 Flow Matching（非自回归）时，Fish Speech 选择了"双自回归"——用两个不同粒度的自回归模型分别处理"说什么"和"怎么说"。

| 路线 | 代表 | 核心假设 |
|------|------|---------|
| **非自回归 (并行)** | CosyVoice, F5-TTS | 并行生成更快，Flow 可以隐式建模时序 |
| **Dual-AR (双自回归)** | **Fish Speech** | 语义和声学建模粒度不同，分开更优 |

---

## 一、整体架构设计哲学

### 核心思想

> **"说什么是语言问题，怎么说是声学问题——让两个不同模型各司其职。"**

关键洞察：一个 TTS 模型其实在做两件事：
1. **语义建模**：理解文本、控制发音——需要深层的语言理解能力（Slow AR）
2. **声学建模**：还原音色、语气、声学细节——需要精细的时序建模（Fast AR）

如果把这两件事塞进一个模型（如 VITS 或 Bark），要么语义理解不够深，要么声学细节不够细。**分开训两个模型，每个可以做到更极致。**

### 架构总览

```
文本 + 参考音频 (Speaker Prompt)
    │
    ├── ① 多语言 LLM (G2P-free)
    │   └── 文本 → 语言特征 (无需字音转换)
    │
    ├── ② Slow AR (语义 Token 生成)
    │   ├── v1.5: ~1B
    │   └── S2: ~4B
    │
    ├── ③ Fast AR (声学 Token 生成)
    │   └── ~400M (两版不变)
    │
    └── ④ 解码器 → 波形
```

## 二、各模块深度解剖（S2 为主）

### 2.1 多语言 LLM 特征提取器

**定位**：提取语言特征，消除传统 G2P（字音转换）依赖。

```
文本: "hello世界"
    │
    ├── 传统 TTS 需要用 G2P 做音素转换:
    │   "hello世界" → [hh, ax, l, ow, sh, ih, j, ye]
    │   → 每种语言需要独立的 G2P 系统和发音词典
    │
    └── Fish Speech S2 用预训练 LLM:
        └── LLM 直接输出语言特征向量
            └── 不需要 G2P，不需要音素词典
```

| 传统 TTS 的 G2P 成本 | Fish Speech 的做法 |
|----------------------|-------------------|
| 每种语言需要：发音词典 + G2P 模型 + 音素词汇表 | 多语言 LLM 直接理解文本 |
| 新增语言：~3 人月 | 新增语言：只需收集音频数据 |
| 对于缺乏语言资源的语言几乎不可行 | LLM 的跨语言迁移能力自动覆盖 |

**S2 支持 ~50 种语言的直接原因**——不是因为它为每种语言训练了 G2P，而是因为多语言 LLM 已经"懂"这些语言。

---

### 2.2 Slow AR（语义 Token 生成器）

**定位**：从语言特征 + 说话人条件生成粗粒度语义 token——确定"说什么"和"基本音色"。

#### S2 配置

| 参数 | v1.5 | S2 |
|------|------|-----|
| 参数量 | ~1B | **~4B** |
| 架构 | Transformer Decoder | Transformer Decoder |
| 注意力 | Causal | Causal |
| 训练数据 | 百万小时级 | **1000 万+ 小时** |
| 输出粒度 | ~20Hz 语义 token | ~20Hz 语义 token |

```
输入: LLM 特征 [T_text, d_lm]
     + Speaker Embedding [d_spk]
     + Prompt 音频 token
    │
    ├── Transformer Decoder (4B)
    │   ├── RoPE 位置编码
    │   ├── Flash Attention
    │   ├── SwiGLU FFN
    │   └── GQA (分组查询注意力)
    │
    └── 输出: 语义 token 序列 [T_sem] @ ~20Hz
```

**为什么 S2 把 Slow AR 从 1B 扩大到 4B？** 实验表明，语义 token 的质量（也就是 TTS 的"内容准确度"）直接受 Slow AR 的容量限制。更大的模型 → 更好的语言理解 → 更低的 WER。S2 的中文 WER 0.54%（v1.5 ~1.2%）的提升主要来自 Slow AR 的扩展。

---

### 2.3 Fast AR（声学 Token 生成器）

**定位**：从语义 token 生成细粒度声学 token——确定"怎么说"（音色、语气、环境）。

```
输入: 语义 token 序列 [T_sem] (来自 Slow AR)
    │
    ├── Transformer Decoder (400M)
    │   ├── 因果注意力（比 Slow AR 更小的模型）
    │   └── 条件: 语义 token + 说话人嵌入
    │
    └── 输出: 声学 token [T_fine, codebook_dim]
```

**为什么 Fast AR 不需要扩大（400M 两版不变）？** 
声学建模的核心是"给定语义 token，预测声学细节"——这是一个确定性的细粒度映射问题，不需要特别强的语言理解能力。400M 的 Transformer 已经足够（对比：HiFi-GAN ~15M 就能做好 Mel→波形）。

#### Dual-AR 的协作流程

```
Step 1: "hello" → LLM → 语言特征
Step 2: 语言特征 → Slow AR(4B) → 语义 token [t_1, t_2, ..., t_20]
Step 3: 语义 token → Fast AR(400M) → 声学 token [c_1, c_2, ..., c_20, ...]
           每个语义 token 对应多个声学 token
Step 4: 声学 token → 解码器 → 波形

总延迟: Slow AR (自回归) + Fast AR (自回归) + 解码
CPU: ~0.5x 实时率
GPU: ~2x 实时率 (SGLang 推理优化)
```

---

### 2.4 内联控制标签

**定位**：通过文本中嵌入自然语言标记控制语气。

```
输入文本示例:
  "[whisper]这个秘密我只告诉你[breath]觉得怎么样？"

支持标签:
  [whisper] — 耳语
  [laugh]  — 带笑声
  [cry]    — 带哭腔
  [breath] — 深呼吸/换气
  [angry]  — 愤怒语气
  [slow]   — 放慢语速
  [fast]   — 加快语速
```

实现方式：这些标签在训练数据中被编码为特殊 token，LLM 和 Slow AR 在训练时学会将标签映射到对应的声学生成模式。

## 三、Fish Speech S2 的 SOTA 指标分析

| 评测 | Fish Speech S2 | 同期最佳 | 人类 | 含义 |
|------|---------------|---------|------|------|
| 中文 WER | **0.54%** | 0.83% | ~2% | 机器听懂率甚至超过人的听写能力 |
| 英文 WER | **0.99%** | 1.26% | ~2% | 英语也破 1% |
| Audio Turing Test | **0.515** | 0.65 | 0.5 | 接近音色无法区分于真人 |

**WER (Word Error Rate) 作为 TTS 评价指标的含金量**：WER 低 = 发音准确 = 内容保真度高。但 WER 不直接衡量音质——一个发音清晰但有"电子音"的模型可能 WER 很低但 MOS 不高。Fish Speech S2 的 WER 优势在于 1000 万小时训练数据 + 4B Slow AR 的语义理解能力。
