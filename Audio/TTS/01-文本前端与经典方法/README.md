# 01 — 文本前端（Text Frontend）

## 一句话开场

> "明天下午 3:30"——这么简单一句话，TTS 怎么知道"3:30"该读"三点三十"还是"三比零"？

## 正文：渐进式理解（3-5 段）

**第一层：问题定义。** 文本前端的任务是把原始文本变成模型可用的语音学表征。具体拆成三个子问题：文本规范化（把 "2024/3/15" 转成该读的文字）、音素转换（把"重"映射到 chóng 或 zhòng）、韵律预测（预测哪里停顿、哪里重读）。为什么非解决不可？因为**前端的错误不可逆**——模型读错了，WaveNet 也救不回来。

**第二层：核心直觉。** 文本前端的本质是"消歧"。同文异音无处不在，但上下文往往不足以解消——"重庆"的"重"读哪个音，没有知识库就是猜。实战中的黄金法则是：80% 的常见情况用正则搞定，20% 的难例用分类模型兜底。

**第三层：方案细节。** 完整流水线：

```text
原始文本 → Sentence Segmentation → Tokenization → Text Normalization
    → G2P（字转音）→ Prosody Prediction → 语言特征序列
```

三个子任务的主流方案：
- **Text Normalization**：WFST 规则系统（传统标准）→ Seq2Seq/BERT 分类器
- **G2P**：中文用查表映射，英文用 Transformer-based 模型
- **Prosody Prediction**：CART → CRF → BERT 序列标注

**第四层：不同方案的权衡。**

| 维度 | 纯规则（Regex+词典） | 规则 + ML 分类器 | 端到端跳过前端 |
|------|---------------------|-----------------|--------------|
| 优点 | 100% 可解释，零成本 | 覆盖面广，歧义消解好 | 训练简单，无前端错误 |
| 代价 | 覆盖窄，维护成本高 | 需标注数据，可控性降低 | 发音不可控，罕见词失准 |
| 适用场景 | 受限领域（导航/播报） | 通用 TTS 产品 | 数据量极大的场景 |

**第五层：总结升华。** 文本前端是 TTS 中**最容易被低估的模块**。在技术演进全景中，它是横跨所有范式（拼接、HMM、神经、大模型）的常量——无论后端用什么黑科技，输入端的中文多音字、英文缩写、数字消歧永远在那里。

## 学习目标

读完你能：

- 拿到一段含数字/日期/缩写的文本，能快速判断其中至少两处歧义并给出不同读法
- 用一句话说清 G2P 和 Text Normalization 分别解决什么问题
- 画出一个完整的文本前端处理流水线
- 面对实际 TTS 项目，判断用纯规则还是 ML 辅助，并说清代价

> 每一条学习目标都能**被客观检验**。

## 精选论文

**Tan et al. (2021) "A Survey on Neural Speech Synthesis" [[arXiv](https://arxiv.org/abs/2103.11203)]**

- **一句话定位**：最全面的 TTS 综述，覆盖经典→神经→大模型完整演进，是学习 TTS 的最佳入口
- **阅读重点**：第 II 节（文本前端）+ 第 III 节（经典方法）
- **时间分配建议**：时间紧只读第 II-IV 节建立全景；时间充裕建议通读
- **与本模块的关系**：提供文本前端的全景概览，以及经典方法的完整介绍

**Taylor (2009) "Text-to-Speech Synthesis"（参考）**

- **一句话定位**：统计参数合成时代的经典教材，文本前端章节至今仍是标准参考
- **阅读重点**：第 5-8 章（文本规范化、G2P、韵律预测）
- **时间分配建议**：不在核心论文中，遇到具体前端问题时翻阅对应章节即可
- **与本模块的关系**：补充了论文中没有的工程细节（WFST 规则设计、韵律标注体系）
