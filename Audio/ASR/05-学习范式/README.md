## 数据不够怎么办？三种路线的选择

前三节讲的 CTC、AED、RNNT 加 Conformer，效果确实好——但它们有一个共同的前提：你有足够的标注数据。具体地说，在 1000+ 小时的标注语音上，Conformer + RNNT 可以达到令人满意的 WER。

问题在于，大部分实际场景并没有 1000 小时标注。你可能就只有几十个小时的普通话标注，想做一个特定领域的 ASR（比如会议纪要或者医疗口述）。这时候你应该怎么做？

过去三四年的进展给出了三条路线。

### 路线一：自监督预训练（wav2vec 2.0）

你的情况是：有大量无标注语音（录起来便宜），只有少量（10h~100h）标注语音。

wav2vec 2.0 的思路是：先用大量的无标注语音训练一个特征提取器，然后在少量的标注语音上 fine-tune 做 ASR。具体来说，预训练阶段做的事情是：把输入语音的某些片段随机 Mask 掉（类似 BERT 的做法），然后模型要做的是"区分真正应该落在 Mask 位置的编码和随机采样的编码"——这是一个对比学习任务。

为什么这个思路特别吸引人？因为无标注语音几乎不要钱——YouTube 上、播客上、会议上，到处都是语音数据，只是没有对应的文本标注。而 fine-tune 阶段只需要极少量的标注——wav2vec 2.0 在 10 分钟标注上的效果就能达到传统系统在 10 小时标注上的水平。

### 路线二：聚类伪标签（HuBERT）

wav2vec 2.0 能工作，但对比学习的设计比较复杂——你不仅要选负例的数量，还得设计量化的方式。HuBERT 换了一个思路：先对语音做 k-means 聚类，生成离散化的伪标签，然后让模型去预测这些伪标签（"预测被 Mask 段落的聚类 ID"）。这个过程可以迭代优化——第一轮生成的伪标签可能质量一般，但模型学完后生成的第二轮伪标签就更好了。

比 wav2vec 2.0 更简洁，效果通常也更好。所以现在自监督 ASR 的主流方案其实已经转向 HuBERT 了。

### 路线三：弱监督大规模训练（Whisper）

Whisper 走了一条和前两条完全不同的路：不要无标注数据做自监督，直接拿 68 万小时 YouTube 自动字幕做"弱标注"——自动字幕的质量远不如人工标注，但量级足够大。Whisper 的 Encoder-Decoder 直接在这么大规模的数据上训，结果一个模型统一了 ASR（多语言）、翻译（X→English）、语言识别三个任务。

Whisper 告诉 ASR 社区一个很可能影响未来几年的结论：**标注质量可以不用那么高，只要数据量级大两个数量级。** 对很多工业场景来说，收集海量弱标注数据可能比精标少量数据更容易落地。

### 怎么选？

你手里有：

- **10h 以下标注** → wav2vec 2.0 或 HuBERT 预训练 + fine-tune
- **10h-100h 标注** → HuBERT（效果通常更好）或者直接用 Whisper（零样本）
- **100h-1000h 标注** → 自监督预训练有收益，但直接训 Conformer + RNNT 已经可以
- **1000h+ 标注 + 不在乎多语言** → Whisper 的方案最省事；或者用自监督提升鲁棒性

## 补充：低资源场景的实用工具箱

### 1. 数据增广 —— 不只有 SpecAugment

Ch01 已经介绍过 SpecAugment（时间和频率掩码），那是 ASR 性价比最高的增广。但有几个同样好用的增广手段：

**速度扰动 (Speed Perturbation)**
对语音波形整体拉伸/压缩，模拟不同语速。主流做法是随机缩放 0.9x、1.0x、1.1x 三个速度。实现简单、计算量极低，但能给 WER 带来 5-10% 的相对提升。Kaldi 的 speed-perturb 加上 fMLLR 是当年最有性价比的 pipeline 提升。

**加噪 (Noise Augmentation)**
从噪声库中随机取一段背景噪声（咖啡馆、街道、风扇等），以随机 SNR（5-20dB）叠加到语音上。训练出来的模型对真实场景的噪声鲁棒性明显提升。MUSAN 数据集是常用的免费噪声库。

**混响 (Reverb Augmentation)**
用房间脉冲响应 (RIR) 对语音做卷积，模拟不同房间的混响效果。常见做法是用真实录制或合成的 RIR 对语音做处理，单条语音可以生成几十个不同"空间感"的版本。

> 对数据量 <100h 的场景，速度扰动 + SpecAugment + 加噪是推荐的最小组合，三行代码就能集成到训练 pipeline 中。

### 2. 微调策略 —— 别直接训全量

拿下预训练模型（wav2vec 2.0/HuBERT/Whisper）后，怎么在你的少量标注数据上微调？

| 策略 | 做法 | 适用场景 |
|---|---|---|
| **Full fine-tune** | 所有参数都更新 | 标注数据 100h+，算力充足 |
| **Adapter Tuning** | 在 Transformer 每层插入小 Adapter 模块，只更新 Adapter | 标注数据 <50h，需要快速实验 |
| **Feature Extraction** | 冻结预训练编码器，只训练一个浅层分类头 | 标注数据 <10h，探索性试验 |
| **LoRA** | 低秩适配矩阵，参数量远小于 Full fine-tune | 大模型（HuBERT Large/XL）微调时显存不够 |

**关键注意事项：**
- 全量微调时要注意**学习率衰减策略**——预训练模型已经是良好的状态，初始学习率应该比从头训练小 1-2 个数量级（一般从 1e-5 起步）
- **灾难性遗忘**：微调过多步数可能导致模型忘记预训练学到的通用语音表征，建议在验证集上做早停
- **领域数据混入**：如果通用数据 + 领域数据都有，混在一起微调往往比只在领域数据上微调效果更好

### 3. 自训练 (Self-Training / Pseudo-Labeling)

当你有大量领域内无标注语音，但只有少量标注数据时，另一种实用的方法：

```
Step 1: 用少量标注数据训一个"老师"模型
Step 2: 用老师模型推理大量无标注数据，生成"伪标签"
Step 3: 用高置信度的伪标签 + 标注数据一起训一个"学生"模型
Step 4: (可选) 学生模型变成新老师，迭代
```

这个方法的关键在于**伪标签的质量控制**：
- 置信度阈值过滤（Token-level 或 Utterance-level）
- 噪声增强后的一致性正则化（Noisy Student Training）
- 迭代轮数控制在 2-3 轮，过多会导致确认偏差放大

> 和 wav2vec 2.0/HuBERT 的区别：自监督学习**在通用无标注语音上**学语音表征，训练过程不依赖特定领域。自训练**在领域无标注数据上**生成伪标签，是针对你想要的场景做的定制。

## 精选论文

**Baevski et al. (2020) "wav2vec 2.0: A Framework for Self-Supervised Learning of Speech Representations" [[arXiv](https://arxiv.org/abs/2006.11477)]**

这篇是自监督 ASR 的里程碑。核心创新就是对比学习 + 量化 + Transformer 的预训练框架。如果你之前不太了解对比学习，这篇可能需要多花点时间在"对比损失函数"上。如果你了解，重点看它的量化设计（为什么需要量化，以及怎么做的）和 fine-tune 阶段的实验——在 10 分钟、1 小时、10 小时标注数据上的提升。

**Hsu et al. (2021) "HuBERT: Self-Supervised Speech Representation Learning by Masked Prediction of Hidden Units" [[arXiv](https://arxiv.org/abs/2106.07447)]**

HuBERT 的论文写得非常清楚（作者来自 Meta FAIR）。重点读它两个部分：（1）迭代伪标签的生成方法——先跑一次 k-means 聚类生成第一轮标签 → 训模型 → 用模型提取特征再做聚类 → 生成更高质量的标签；（2）为什么简单的 MSE 损失在聚类伪标签上就管用，不需要对比学习的复杂设计。

**Radford et al. (2022) "Robust Speech Recognition via Large-Scale Weak Supervision" [[arXiv](https://arxiv.org/abs/2212.04356)] (OpenAI Whisper)**

Whisper 的论文篇幅不长，但实验量很大。不需要逐字读完——读它的数据集构建方法（怎么筛选 68 万小时的弱标注数据、怎么处理噪声数据）和模型的设计选择（为什么用 Encoder-Decoder 而不是纯 Encoder、为什么做多任务训练）就够了。它的"弱监督"结论对所有从业者有启发意义。

## 本章思考题（附解答）

### 基础层

#### Q1：自监督学习（Self-Supervised）和弱监督学习（Weakly-Supervised）的根本区别是什么？

**A：**

| 维度 | 自监督（wav2vec 2.0 / HuBERT） | 弱监督（Whisper） |
|---|---|---|
| **要不要标注？** | 不要。预训练完全不需要文本，只用语音本身 | 要。有自动生成的文本标注，但质量不高（自动字幕） |
| **数据来源** | 海量无标注语音（播客、会议录音） | 海量弱标注语音（YouTube 自动字幕） |
| **质量要求** | 语音质量无所谓，但不能有标注噪声 | 标注可以很粗糙，但不能太偏离音频内容 |
| **核心假设** | 语音本身的统计结构足以学到良好表征 | 大量低质标注 > 少量高质标注 |
| **典型代表** | wav2vec 2.0, HuBERT | Whisper |

**一句话区别：**
- 自监督：**"我给你大量语音，不需要告诉我内容，我自己学。"**
- 弱监督：**"我给你大量带粗糙标注的语音，标注不完美但够用。"**

两者在低资源场景下都可以有效利用，但适用的前提条件不同——如果你有大量纯音频，走自监督；如果你能低成本拿到弱标注，走弱监督。

#### Q2：wav2vec 2.0 的预训练过程核心思想是什么？对比学习具体在做什么？

**A：**

wav2vec 2.0 的核心思想：**用对比学习让模型学会"哪些语音片段属于同一个句子"**。

具体流程：

```
原始语音 → CNN 特征提取器 → 离散化（量化） → Transformer → 对比损失
                │                                 ▲
                ▼                                 │
            随机 Mask 部分片段 ─── 被 Mask 的位置需要从上下文中恢复
```

**对比学习的具体含义：**

对于被 Mask 的位置，模型会看到一个"候选集合"：
- **正例**（Positive）：从量化模块中选出的、与当前 Mask 位置匹配的编码
- **负例**（Negative）：从其他位置或句子中随机采样的编码

模型的损失函数是 InfoNCE（一种对比损失）：

```
L = -log( exp(sim(正例)) / (exp(sim(正例)) + Σexp(sim(负例))) )
```

直观理解：模型需要在 K+1 个候选中选出正确的那一个。负例数量（K）越大，任务越有挑战性，学到的表征越好。wav2vec 2.0 通常设 K=100。

**量化的作用**：连续的特征通过 Gumbel Softmax 变成离散编码——因为离散化迫使模型丢弃不重要的细节，只保留对内容识别关键的语音结构。

#### Q3：HuBERT 相比 wav2vec 2.0 做了哪些简化？为什么改完之后效果更好？

**A：**

核心简化：**扔掉对比学习 + 量化，换成 k-means 聚类 + MSE 预测。**

对比维度：

| | wav2vec 2.0 | HuBERT |
|---|---|---|
| 学习任务 | 对比学习（区分正负例） | 预测聚类 ID（类似 BERT 的 MLM） |
| 离散化方式 | Gumbel Softmax + 量化器 | k-means 聚类（仅在预处理阶段跑一次） |
| 损失函数 | InfoNCE 对比损失 | MSE + 交叉熵 |
| 负例设计 | 需要精心选择负例（K 值、采样方式） | 不需要负例 |
| 迭代优化 | 无 | 有：聚类→训练→再聚类→再训练 |

**为什么更简洁但效果更好：**

1. **预测任务比对比任务更直接**——预测被 Mask 的聚类 ID 就是"猜这个帧是什么声音"，是一个更自然的语音学习目标
2. **不需要负例工程**——对比学习的负例数量、采样策略都在影响效果，HuBERT 完全躲开了这个问题
3. **迭代优化的正反馈回路**——第一轮 k-means 生成的标签可能质量一般（只是 MFCC 的聚类），但模型学会后提取出的特征再做聚类，第二轮标签就含有了更高层次的语义信息

**迭代流程：**

```
Round 1: 原始 MFCC → k-means → 聚类标签 A (粗糙)
         ↓ 用标签 A 训练 HuBERT 模型
Round 2: HuBERT 隐藏层特征 → k-means → 聚类标签 B (更好)
         ↓ 用标签 B 重新训练 HuBERT 模型
Round 3: (同上) → 聚类标签 C (最好)
```

最终 HuBERT 的效果在 LibriSpeech 上全面超越 wav2vec 2.0，而且代码实现更简单。

### 应用层

#### Q4：你只有 50 小时的中文医疗口述标注数据，想做领域 ASR。推荐哪种方案？

**A：**

```
数据情况分析：
- 标注量：50小时（处于"10h-100h"区间）
- 领域：医疗（词汇特殊，常见短语与通用场景不同）
- 语言：中文（与英文不同，中文没有空格分割的"词"边界）
```

**推荐方案优先级：**

① **HuBERT 预训练 + 领域微调**
  - 收集 1000+ 小时无标注中文语音（播客、新闻广播、公开医疗讲座）
  - 用 HuBERT 做预训练 → 得到中文通用语音表征
  - 在 50 小时医疗标注上做 full fine-tune
  - 预期收益：在通用场景 WER 可降低 30-50%，领域内效果更好

② **Whisper zero-shot + 领域微调**
  - Whisper large-v2/v3 已经支持中文，可以在 50h 医疗数据上微调
  - 优势：不需要预训练步骤，直接微调 Whisper 即可
  - 注意：Whisper 不支持流式，只适合"录完再转"场景

③ **直接训 Conformer + RNNT**
  - 如果算力和时间有限，直接从零训一个小模型
  - 需要配合强数据增广（Speed Perturb + SpecAugment + 加噪）
  - 上限可能不如前两个方案，但工作量大

**建议验证流程：**
```
1. 先评估 Whisper zero-shot 在医疗数据上的基线 WER
2. 收集领域内无标注语音（医疗讲座、问诊记录）
3. 训练 HuBERT 或直接微调 Whisper
4. 对比三种方案，选最优部署
```

#### Q5：在数据增广中，速度扰动、加噪、混响的参数一般怎么设置？

**A：**

以下是工业界常用的默认配置，大多数场景可以直接复用：

**速度扰动 (Speed Perturbation)：**

| 参数 | 推荐值 | 说明 |
|---|---|---|
| 速度因子 | 0.9, 1.0, 1.1 | 三路复制，每条语音随机选一个 |
| 实现方式 | SoX / librosa | `tempo -s` 保持音调不变 |
| 数据量翻倍 | 3x | 每条语音生成 3 份不同速度版本 |

**加噪 (Noise Augmentation)：**

| 参数 | 推荐值 | 说明 |
|---|---|---|
| SNR 范围 | 10-20dB（干净场景） | SNR 越低噪声越大 |
| | 5-15dB（强鲁棒） | 适合嘈杂环境部署 |
| 噪声来源 | MUSAN / AudioSet | 包含 930 段噪声（咖啡馆、白噪声、自然声） |
| 噪声混入比例 | 30-50% | 太低频：学不到；太高频：变成主要信号 |

**混响 (Reverb Augmentation)：**

| 参数 | 推荐值 | 说明 |
|---|---|---|
| RIR 来源 | OpenSLR / Reverb Lab | 真实录制的 RIR（小房间、大房间、办公室等） |
| 混入概率 | 20-30% | 太多会改变语言风格 |
| 常用组合 | 加噪 + 混响串联 | 先加混响再加背景噪声更真实 |

> **最小推荐组合**（算力有限时）：Speed Perturb (0.9,1.0,1.1) + SpecAugment (F=10, T=50)。两行配置就能带来 10-15% 的相对 WER 下降。

#### Q6：假设你有 500 小时领域内无标注语音，只有 20 小时标注。设计一个自训练（Pseudo-labeling）流程。

**A：**

推荐流程如下：

```
Step 1: 用 20h 标注数据训一个 Baseline 模型（Conformer + CTC 最简单）
           ↓
Step 2: 用 Baseline 推理 500h 无标注语音，生成伪标签
           ↓
Step 3: 过滤伪标签（保留置信度 > 0.9 的句子）
           ↓
Step 4: 用 20h 人工标注 + 筛选后的伪标签训 Student 模型
           ↓
Step 5: (可选) Student 变 Teacher，重复 Step 2-4
```

**关键细节：**

**① 伪标签过滤标准：**
- Utterance-level 置信度：解码时的平均 log-probability > 阈值
- Token-level 置信度：看是否有低置信度的片段集中出现
- 如果用的是 CTC，可以看 Blank 占比——异常低的 Blank 比例通常意味着模型"过度自信"幻觉

**② 迭代控制：**
- 通常 2-3 轮即可收敛
- 第一轮提升最大（+15-25% relative），后续每轮边际递减
- 超过 3 轮容易放大初始模型的错误 → 确认偏差

**③ 增强学生训练（Noisy Student）：**
- 推荐在训练 Student 时对学生输入做数据增广，而 Teacher 推理时不增广
- 这样 Student 学到的不仅是伪标签，还是"即使在有噪声条件下也能正确识别"
- Google 用这个策略在 LibriSpeech 上再降了 10-15% WER

> **和 HuBERT 对比**：自训练本质上是用领域数据做"知识蒸馏"。HuBERT 是用通用数据学通用语音表征——两者可以结合使用：先用 HuBERT 预训练，再用自训练做领域适配。

### 评价层

#### Q7：Whisper 论文的核心结论是"标注质量不用那么高，量级大两个数量级就行"。这个结论有没有边界？

**A：**

结论成立有边界，以下场景中可能不成立：

**① 高噪音/远场场景**
- YouTube 自动字幕大多是配音、演讲、播客——信噪比普遍较高
- 如果你的部署场景是嘈杂的工厂（SNR < 5dB），弱标注数据中很少有这种环境
- Whisper 在极端噪声下的表现不如专门的 Robust ASR 模型

**② 方言 / 混合语码**
- YouTube 字幕以标准语言为主，方言和混合语码（如 Hinglish、Singlish）的代表性不足
- 在缺乏方言弱标注的情况下，"量大"不能解决"分布不匹配"的问题

**③ 领域术语丰富的场景**
- 医疗、法律、金融领域的专有名词在 YouTube 上的分布很稀疏
- 对于 Latent 的领域知识，弱标注的数量优势会被质量门槛抵消

**④ 实时/流式场景**
- Whisper 的 Encoder-Decoder 结构天然不支持流式（需要听完整句才能解码）
- 它的弱监督结论只适用于离线场景

**修正后的理解：**
```
Whisper 的结论成立条件：
✓ 语音环境相对干净（接近 YouTube 分布）
✓ 语言以标准语音为主
✓ 任务为离线转录
✗ 极端噪声、方言、领域术语密集、流式场景
```

> 对工业项目的启示：Whisper 是一个极其强大的基线，但不要假设它在任何场景下都是最优解。先在自己的领域数据上评估 Whisper zero-shot 的 WER，再决定是微调 Whisper 还是走自监督路线。

---

#### Q8：如果你在一个工业项目中需要做决策：用自监督（HuBERT）还是弱监督（Whisper）？你会从哪些维度分析？

**A：**

决策树如下：

```
你有多大的标注数据量？
├── < 10h → 看有没有算力？
│   ├── 有：HuBERT 预训练 + fine-tune (收益最大)
│   └── 无：Whisper zero-shot (不需要训练)
├── 10h-100h → 看任务场景？
│   ├── 离线转录：Whisper 微调 (省事, 效果好)
│   └── 流式任务：HuBERT + RNNT (流式必须走自监督/直接训)
└── 100h+ → 你怎么看 ASR 的长远规划？
    ├── 需要掌控全链路：自监督 HuBERT → 领域微调
    └── 快速上线：Whisper 微调 (但注意流式限制)
```

**详细维度分析：**

| 决策维度 | 偏向 HuBERT 的情况 | 偏向 Whisper 的情况 |
|---|---|---|
| **标注数据量** | < 100h 标注 + 有大量无标注语音 | 有 100h+ 弱标注数据或用 zero-shot |
| **流式需求** | 需要低延迟流式 ASR | 不需要流式（录完再转） |
| **算力资源** | 有 GPU 集群做预训练（耗时） | 有 GPU 做微调（更快） |
| **语言覆盖** | 单一语言、无多语言需求 | 多语言需求 |
| **部署环境** | 移动端/嵌入式（模型小） | 云端（模型大没关系） |
| **数据隐私** | 数据不能出本地，需要自训 | 可用通用 Whisper（不涉及私域） |
| **维护成本** | 需要维护预训练 + 微调 pipeline | 简单微调，Whisper 社区活跃 |

**工业场景建议：**
1. **先评估 Whisper zero-shot**——它可能是最快的"第一版"基线，零成本
2. **如果 Whisper 不满足需求**（延迟/精度/离线），走 HuBERT
3. **最后考虑混合策略**——Whisper 做伪标签生成 → 自训练蒸馏到流式小模型
